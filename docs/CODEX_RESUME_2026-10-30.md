# uCode-Bench — точка продолжения работы Codex после перерыва

**Контекст зафиксирован:** 30.10.2026. **Статус:** передача фактов, а не разрешение автоматически обновлять/удалять/сливать ветки.

Этот файл — **наиболее свежая операционная инструкция** по состоянию на конец 30 октября. Ранние разделы `AGENTS.md`, `docs/AI_HANDOFF.md`, `docs/SINGLE_FOLDER_PLAN.md` и `docs/REPORT_ONLY_TESTS.md` были написаны **до** миграции рабочих папок. В части локальной структуры и очистки их исторические запреты не являются текущим описанием: выполненные операции уже проверены пользователем. Исходники и релизы сверяй с актуальным Git/GitHub, а не со старыми текстовыми обещаниями.

## 1. Зачем и что сделали после прерывания Codex

Пользователь хочет **один рабочий проект на системном диске**, весь старый объёмный тестовый вывод — отдельно на другом диске, а GitHub — для исходников и проверенных релизов. Тесты измеряют фактическое кодирование + создание и запись PDF + QA, но не должны бесконечно накапливать PDF и много-ГиБ рабочие базы. **Производственная кнопка «Создать PDF» обязана сохранять файлы.** Нельзя переносить новые скоростные тесты на другой носитель незаметно: это меняет сравниваемую производительность.

Пользователь выполнял операции вручную через Git Bash Here. Ассистент в ChatGPT **не имел доступа к его дискам**, не запускал команды и не выполнял локальных Git операций. Факты ниже подтверждены присланными логами.

Подтверждено:
- Первоначально было три **связанных Git worktree одного репозитория**, а не три отдельных проекта: `016_uCode` (основной), `016_uCode_PDF_test`, `016_uCode_GitHub_preview`.
- В `PDF_test/output/jobs` выявлено 5257 PDF суммарно 7.64 ГиБ, 2921 SQLite суммарно 10.69 ГиБ (из них два `data.sqlite` примерно по 3.87 ГиБ), остальное — отчёты и другие тестовые файлы. Это **не** означает, что все SQLite — несущественные базы: `catalog.sqlite` является индексом архива тестов и должна сохраняться.
- Семь каталогов `output`/`results`/`.local-state` из трёх worktree собраны в архив `uCode-history-2026-10-30.tar.gz` (~6.2 ГиБ, 89 042 записи). `sha256sum -c` => OK. Архив распакован в `uCode_Archive/History-2026-10-30` на другом диске; **все семь** каталогов прошли `diff -qr` с исходниками => PASS 7/7.
- Только после повторной проверки удалена **исключительно исходная папка** `016_uCode_PDF_test/output` на системном диске; восстановленная копия и `.tar.gz` остались на другом диске.
- Оставшиеся два worktree скопированы с полным содержимым за исключением служебных `.git` в `uCode_Archive/Worktrees-2026-10-30`. `diff -qr --exclude=.git` подтвердил PASS 2/2. Независимый `uCode-git-history.bundle` проверен `git bundle verify` (71 ссылка).
- Все **8 локальных Codex WIP** в старом `PDF_test` предварительно проверялись по blob: идентичны содержимому сохранённого Git-коммита `f70f748`. Перед отключением worktree пользователь выполнил `git stash push --include-untracked` с сообщением `Backup uCode PDF test before worktree cleanup 2026-10-30`. Stash сохраняет 5 modified + 3 untracked файлов. Финальный `uCode-git-history-final.bundle` создан **после stash**, успешно проверен, включает ссылку `refs/stash`; сама копия WIP-файлов дополнительно сохранилась в архиве worktree.
- Оба дополнительных worktree штатно отключены `git worktree remove --force` **после** создания резервных копий и проверки чистоты. Финальная команда `git worktree list` показала только `016_uCode`.
- Последний пользовательский вывод: основной worktree `016_uCode`, `feature/txt-batch-print-pdf-20261027`, **HEAD `c30c97c`**, `git status -sb` чисто, **behind 8** относительно tracking-ветки на момент проверки. Есть `Start-uCode.cmd`, `.venv` (~306 МБ), `tools` (~395 МБ), `output` (~124 МБ), `results` (~731 КБ). Свободно на C: около **27 ГиБ** против 5.7 ГиБ в начале. Никакого `git pull`/rebase/merge в основной worktree не выполнялось.

**Важно:** копии и архивы описаны относительно корня `uCode_Archive` на отдельном носителе. Абсолютные пути, содержимое личного файла переписки и большие локальные тестовые данные **не публиковать** в репозитории.

## 2. Что происходило в последнем диалоге с Codex

Пользователь сохранил на своей машине отдельный документ `code_codex_dialog_txt_2026-10-30_.md` (вне репозитория). Этот фрагмент переписки **не загружен в GitHub**; Codex с локальным доступом может прочитать его по пути, указанному пользователем. Ниже — технический конспект.

**QR и коррекция ошибок:**
- В консоли uCode выполнялись 4 отдельных прогона по **10 000 QR**, ECC `L / M / Q / H`, 14 процессов, один PDF на прогон, без warmup и **без QA**. Сообщённые времена QR + запись PDF: **6.21 / 6.27 / 6.33 / 6.28 секунды**, скорость **1610 / 1596 / 1580 / 1592 кодов/сек**; суммарная очередь ~29.54 с. Результаты только **UNVERIFIED**: нельзя превращать их в QA PASS или выводить устойчивое преимущество по одному измерению. Исторический отчёт `commands.html` был под старым `PDF_test/output/jobs/tests/console/...`; физически он теперь в `History-2026-10-30/016_uCode_PDF_test/output/jobs/...` на архивном диске, прежний `file:///C:/...` больше не существует.
- Для 12 цифр при 0.5 мм/модуль и 4 модулях поля все ECC L/M/Q/H помещались в матрицу 21×21 и физический размер 14.5×14.5 мм. Рост размера при ECC происходит **ступенчато по версии QR**, не всегда.
- Реализованы локальные payload-шаблоны QR: текст, URL, e-mail, телефон, SMS, контакт, Wi-Fi, WhatsApp, календарное событие, координаты и ссылки на файлы/соцсети. Codex сообщил об успешной локальной проверке кодирования/чтения и малой PDF QA, commit `c272299`. **Этот коммит не является HEAD основной рабочей папки `c30c97c`**; наличие реализации в текущем запуске проверять, не предполагать.
- После этого пользователь запросил **передаваемые без отдельно установленного Python** сборки: Windows `uCode.exe`, macOS `uCode.app`, Linux переносимый исполняемый пакет; независимые сборки в GitHub Actions; проверка системных зависимостей; стабильный релиз базовой версии и затем обновления через GitHub Releases с подтверждением и откатом.
- Codex **начал** подготовку, сообщил об редактировании файлов, но лимит прервал его прежде, чем в переписке появился подтверждённый результат упаковки. Показан сброс лимита 04.11.2026 09:38 (из UI пользователя, не гарантированный фактический статус его доступа). **Нельзя считать задачу сборок законченной по этому диалогу.**

## 4. С чего начинать Codex при возвращении

1. Определи, есть ли **реальный доступ** к Windows-дискам пользователя. Если облачная среда не видит `016_uCode` и архивный носитель — не утверждай, что изучил эти файлы. Используй GitHub и пользовательские диагностические выводы, запроси только необходимые данные.
2. В режиме **только чтение**: `git status -sb`, `git worktree list`, `git stash list`, `git branch -avv`, `git remote -v`, последние коммиты; осмотри `Start-uCode.cmd`, структуру сборки и код из `c272299`. Подтверди единственную рабочую папку и сохранённый stash.
3. Сверь текущие PR #28/#29/#30, их HEAD, CI и зависимости. **Не** выполняй `stash pop`, `git pull`, `checkout`, `reset --hard`, `clean`, удаление веток или архивов автоматически.
4. Обнови историческую документацию `AGENTS.md`/`AI_HANDOFF.md`/`SINGLE_FOLDER_PLAN.md`, отделяя зафиксированные факты от прежних планов. Этот файл является свежим дополнением, а не подтверждением, что локальная машина уже перешла на PR #30.
5. Предложи один безопасный путь продвижения новой разработки с сохранением однопапочной структуры, синхронизацией исходников и резервным откатом. Сначала изолированный рабочий шаг, затем малые тесты и пользовательская приёмка; **никакой** массовой миллионной генерации без явного запроса.
6. Закончить переносимый packaging, проверить реальные бинарники для каждой платформы и системные предпосылки, затем отдельно реализовать безопасную установку обновлений; нельзя называть текущий `--check` полной системой обновления. Производственный PDF не удалять.
7. После завершения этапа дополнять `docs/WORK_LOG.md` конкретными commit SHA, CI-ссылками, проверками и следующим шагом. Любое изменение `main` или релиза — только после QA и пользовательского решения.
