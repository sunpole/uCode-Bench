# Настраиваемые тесты без пресетов — 28.10.2026

Ветка `codex/custom-test-controls`, основа `2a171b8`, тестовая копия `016_uCode_PDF_test`. По уточнённому запросу пользователя главный сценарий — самостоятельно задать количество кодов, отметить режимы CPU и число повторов. Это не фиксированный пресет «2000/1/все» и не автоматический большой прогон.

## Управление

Закройте прежнее окно, откройте **Start-uCode.cmd** этой тестовой копии и вкладку **Тесты** (либо **Тесты → Настроить и запустить тесты**).

1. **Количество кодов:** одно число от1 до10000, например `2000` или `10000`. Пробел в `2 000` также допустим.
2. **Повторов каждого режима:** от1 до10. Значение1 означает один запуск, не три. В новой копии default1, уже сохранённое значение остаётся видимым.
3. Выберите физические ядра либо логические CPU и отметьте необходимые кнопки-галочки. Количества берутся из текущего ПК; недоступные отключены. «Все» содержит реальное число. Галочки — отдельные режимы, не сумма.
4. До старта виден расчёт и порядок: **2 режима ×1 повтор =2 запуска** или **3 режима ×10 повторов =30 запусков**. Повторы каждого режима выполняются подряд, затем следующий режим. Числовые CPU-режимы упорядочены по возрастанию, далее all-2/all. Если выбранные режимы совпадают либо несовместимы, простой запуск блокируется с причиной, без скрытых пропусков.
5. Нажмите единственную основную кнопку **ЗАПУСТИТЬ ТЕСТЫ**. Она занимает место СОЗДАТЬ PDF при выборе вкладки тестов; TXT для лабораторных номеров выбирать не нужно.
6. Каждая строка в окне — отдельный проход: CPU, номер повтора, создание PDF/QA/полный цикл в секундах и статус. Страницы переключаются стрелками. Количество кодов исходного результата указано возле таблицы, даже если поле будущего теста уже изменено.
7. **Все результаты (N)** открывает браузерную таблицу всех строк сразу, с CSV и сводкой среднего/минимума/максимума по каждому успешно завершённому режиму. В исходной comparison.html тоже есть ссылка на все отдельные запуски.

Примеры параметров, не готовые пресеты:

- `2000`, повторы `1`, галочки `1` и `Все` → ровно2 запуска и2 строки.
- `10000`, повторы `10`, галочки `2`, `4`, `12` → ровно30 запусков и30 строк.

## Что используется и как читать результат

В основном управлении изменяются только количество, CPU-режимы и повторы. Скрытые списки PDF/методов/RAM не перемножают этот план. Каждый запуск создаёт один реальный многостраничный QR-PDF; геометрия/цвет/PDF-профиль берутся из текущих настроек печати. Одна стратегия: process encoding, auto RAM, обычный сбор метрик; QA полная, прогрев0. Число workers соответствует разрешённым CPU, партия до32 уменьшается для малого объёма, пул ограничивается числом задач. Это не обещание100% загрузки каждого ядра: запись PDF/QA последовательны, при малом количестве кодов workers может быть меньше разрешённой маски. Фактическое число сохранено в отчёте.

**Все параметры…** открывает прежнюю расширенную матрицу: несколько PDF/activity/backend/RAM, прогрев, партия/workers и собственный CPU-список. Вместо таблицы результатов в той же панели появляются эти настройки. Кнопка возврата восстанавливает основное управление. Исторические научные200→1000→10000/gates/три повтора не изменены и вынесены в отдельное подменю научных тестов объединения.

`PDF, сек` — измеренное производство до QA; `QA, сек` — проверка; `Всего, сек` — измеренная партия с QA. Контрольная оболочка/предварительные проверки отдельно в полном comparison/JSON; её время не приписывается PDF. Общий секундомер показывает время серии.

Рекомендация использует только полные повторы с QA PASS и медиану времени с проверкой при одинаковых остальных параметрах. При различии до5% предлагается меньше CPU, без заявления о статистическом равенстве. При одном проходе это один измеренный результат, не доказанная устойчивость на другом объёме/ПК. Неполные/ошибочные/ограниченные варианты не получают общего победителя. Отмена сохраняет выполненные данные; оставшиеся строки явно NOT_RUN и без вымышленных времён.

Файлы каждого нового run: прежние `lab.json`, `comparison.html/csv`, `ОТЧЁТ.txt`, trials/PDF плюс **all-results.html** и **all-results.csv**. Выгрузка строк создаётся один раз после серии, вне измерений отдельных PDF, не на каждый код. Старые результаты не перезаписываются.
