# 0.3.1 — рабочая HTML-вёрстка в десктопном окне

Рабочая ветка `codex/v031-desktop-webview`. Релиз не опубликован, main не изменён.

## Запуск и возврат

1. В тестовой копии один раз `Setup-Desktop.cmd`: зависимости только в `.venv`.
2. `Start-uCode.cmd` или `.venv\Scripts\python.exe -m ucode gui`: отдельное окно.
3. `Start-uCode-Browser.cmd` / `python -m ucode gui-browser`: прежний браузерный запуск.
4. `Start-uCode-Legacy.cmd`: старый Tkinter.

На этом ПК pywebview уже установлен. Нужны Python 3.10+, pythonnet/.NET и Microsoft WebView2 Runtime. Системный Runtime автоматически не устанавливается; при отсутствии движка нет тихого перехода на IE. Установку Microsoft Runtime пользователь выполняет отдельно. Нет Electron, Node.js и нового PDF-движка.

## Архитектура

`operator_desktop` создаёт одну pywebview/WebView2. Используются прежние `operator_web`, защищённый loopback API, `operator_service`, отдельные процессы генерации. Мост JS имеет только `finish_close`, без доступа к нативному дереву объектов. Внешние target=_blank открываются в стандартном браузере. Профиль WebView хранится в `.local-state/webview-profile`, режим private.

Отдельная OS-блокировка окна дополняет существующую блокировку сервера. Повторный запуск активирует окно того же PID. Если уже есть старый браузерный сеанс, окно подключается к нему; новый генератор не создаётся. После закрытия незанятого окна сеанс завершается. Во время работы крестик/Alt+F4 вызывают прежнее подтверждение остановки с серверной задержкой 3 секунды. «Продолжить» отменяет закрытие; подтверждение останавливает собственную операцию, затем закрывает окно. При потере связи закрытие не считается доказанно безопасным и отклоняется; это консервативное ограничение, требующее отдельной диагностики при возникновении.

Утверждённый HTML и все 18 исходных style-блоков неизменны. Дополнительный `operator-window.css` ограничивает высоту окна: шапка и подвал стабильны, центр растягивается, содержимое вкладок и подробная статистика имеют внутреннюю прокрутку при недостатке места. Размеры шрифтов не уменьшаются. Минимальное внешнее окно 900×560 логических единиц. WebView `zoomable=False` защищает от случайного Ctrl+колесо; масштабирование Windows сохраняется. До создания окна запрашивается Per-monitor DPI V2, для старых систем — доступный fallback. Перенос между физическими мониторами не проверен.

## Короткие проверки

`python -m unittest tests.test_operator_desktop tests.test_operator_web tests.test_operation_host tests.test_operator_models -q`

`node --check ucode/assets/operator-bridge.js`

`node --test tests/operator_controls.test.cjs`

20 Python-тестов и 2 Node-теста прошли. Node нужен только для разработки.

Одна команда реальной диагностики, без скриншотов и больших нагрузок:

`.venv\Scripts\python.exe scripts\desktop_smoke.py`

Создаёт отдельную папку `output/desktop-smoke/<id>` и `result.json`: реальная WebView2, 3 кода/3 страницы PDF с независимым структурным декодированием (LIMITED, без растровой проверки), геометрия 1200×800 → 1000×700 → 900×560 → 1200×800, 8 вкладок, повторный запуск и закрытие сервера. Команда создаёт временное видимое окно, затем сама закрывает. Не запускает пользовательский тираж и не трогает его исходные файлы.

Первый реальный запуск выявил обход публичного native-объекта в JS-мосте; исправлен отдельным узким мостом. Первые PDF-smoke содержали несовместимый тестовый набор serial+CPU affinity; исправлен сам сценарий на один реальный process/logical CPU, производственная CPU-логика не менялась. Обнаруженное превышение нижней границы на малом окне исправлено CSS-ограничениями. Все первые отчёты оставлены локально; успешный повтор не стирает ошибки.

Нет измеренного ускорения QR/PDF от оболочки. Полные тиражи, Linux WebView, чистая установка Windows и формальная визуальная/DPI-приёмка не проверялись.

## Приёмка пользователем

| Действие | Ожидаемый результат |
|---|---|
| Запустить Start-uCode.cmd; затем повторить | Одно окно без браузерных вкладок; повтор активирует его |
| Обычное / развёрнутое / минимальное окно | Основные действия доступны; список прокручивается внутри; нет общей горизонтальной прокрутки |
| Windows 100%, 125%, 150%; смена монитора | Читаемые шрифты, без наложений; QR квадратный; при тесном окне содержимое прокручивается |
| Открыть свой TXT, выбрать первую/последнюю строку | Верные номера и соответствующий QR |
| Проверить «Путь», создать маленький PDF | Файл открывается; число страниц совпадает; QA соответствует выбранному режиму |
| Во время работы крестик/Alt+F4 → «Продолжить» | Окно и операция продолжают работу |
| СТОП или крестик → дождаться 3 сек → остановить | Останавливается только собственная операция; частичные результаты сохраняются; при запросе закрытия окно закрывается |
| Закрыть незанятое окно | Процессы этой сессии завершаются; повторный запуск работает |

Обновлять через новую папку либо чистую отдельную ветку, не перезаписывая локальные изменения. Для возврата достаточно браузерного launcher: настройки, результаты и утверждённый макет общие, удаления не требуется.
