# uCode Development Auto Update — кандидат, 2026-10-31

## Цель

Обновлять Windows uCode из графического интерфейса без Git Bash:
**Development → Development** по исходному SHA, а не по неизменному
прикладному номеру 0.3.4. Stable и Development остаются независимыми.

## Поставка

- При изменении main GitHub Actions запускает Portable Preview для
  Windows/Linux/macOS, выполняет настоящую проверку EXE, QR и PDF.
- Отдельный workflow `.github/workflows/publish-development.yml` после
  успешной сборки публикует **prerelease** с неизменяемым тегом
  `dev-<40-символьный SHA>`. Он проверяет, что сборка получена из
  актуального main, исходный SHA совпадает с `build-info.json`, а ZIP
  соответствует SHA256SUMS.txt.
- Каждый кандидат содержит Windows ZIP, SHA256SUMS.txt и development.json.
  Он НЕ становится `releases/latest` и не изменяет stable v0.3.4.
- Пока source репозиторий публичный, пакеты доступны без GitHub CLI.
  **Перед переводом uCode-Bench в PRIVATE необходимо перенести выпуск
  этих пакетов в публичный uCode**. Автообновление приватных релизов
  без доступа к ним работать не будет.

## Установщик и GUI

- `uCode.Updater.exe 0.3.0 --check-dev --current-sha <SHA40>`.
- `--install-dev --current-sha <SHA40> --accept [--wait-pid PID]`.
- `--rollback-dev --accept`, `--launch-dev`.
- Вкладка «Обновление» позволяет вручную выбрать Stable или Development,
  проверить выбранный канал, увидеть проверенный кандидат, подтвердить
  установку и следить за этапами процесса.
- Development устанавливается в
  `%LOCALAPPDATA%\uBrand\uCode-Dev\versions\dev-<SHA>\uCode`.
  В постоянной папке остаётся launcher и отдельный ярлык
  «uCode Development», не перезаписывающий старый.
- TXT, PDF, настройки и журналы хранятся отдельно:
  `%LOCALAPPDATA%\uBrand\uCode`.
- ZIP проходит проверку размера, SHA256, безопасную распаковку,
  соответствие встроенной build-info и настоящий `uCode.exe --smoke`
  прежде, чем новая версия становится текущей.
- Предыдущая управляемая Development-версия сохраняется для отката.

## Скриншотер

- Stable v0.3.4 уже сохранена в ветке history-gallery: 8 PNG + manifest.
- Новые stable Releases пополняют историю автоматически.
- Development интерфейс проверяется и снимается в PR и после обновлений
  main. Временные dev-снимки хранятся в GitHub Actions Artifacts;
  история релизов хранится постоянно. Не выдавать dev за stable.

## Ограничения до готового выпуска

Код из этого PR не является проверенным конечным релизом. Нужно дождаться
Windows CI, проверить из окна два последовательных dev-выпуска
(скачивание → установка → закрытие окна → запуск → откат), проверить
сеть/повреждённый ZIP/недостаток места/занятый файл/выключение Windows.
Первый переход с прежнего portable uCode 0.3.4 к управляемому
установщику требует одного безопасного перехода. Никогда не заменять
файлы старого stable до результата этих тестов.

Контрольные суммы из того же релиза защищают от повреждения и позволяют
сверить поставку, но НЕ заменяют подпись издателя. Для критичной
дистрибуции предусмотреть отдельную подпись.
