# История тестов внутри программы — P07/P08, 28.10.2026

Основа `dbf047b`, ветка `codex/test-history-p07`. Отдельный набор **12 задач** для истории новой лаборатории CPU / PDF, не закрытие всех P07/P08 и не новый нагрузочный benchmark. Тестовая копия — `016_uCode_PDF_test`. Зависимости/система/main не меняются.

## Как пользоваться

Перезапустите **Start-uCode.cmd** тестовой копии. Вкладка **История** или **Тесты → История тестов CPU / PDF** открывает результаты из выбранной **Папки PDF/laboratory/**.

1. **Мои тесты** возвращает текущую папку лаборатории, **Другая папка…** выбирает другую историю либо папку одного запуска с lab.json. **Обновить** перечитывает результаты. Папки/файлы при этом не создаются.
2. Видны дата файла (UTC), имя запуска, тиражи и статус. Поиск ищет по дате, имени, тиражу и статусу. Фильтр оставляет успешные или проблемные результаты.
3. Выберите запуск и нажмите **Замеры →** (или двойной щелчок). Таблица показывает количество кодов, фактически выделенные ядра/потоки, метод/профиль PDF и медианы создания/с QA. Прогрев исключён. Назад — **← Запуски**.
4. **Отчёт в браузере**, **PDF**, **Папка** открывают исходные сохранённые файлы. PDF выбирается из непрогревочной попытки. Если файл удалён/перенесён или ссылка выходит за пределы выбранного запуска, кнопка недоступна либо выводится понятная причина.
5. Страницы переключаются **‹ / ›**. На экране 4 строки, при150% — 3: главное окно остаётся без прокруток на1366×768. Поиск/фильтр действуют на весь прочитанный список, не только видимую страницу.

**QA PASS*** означает сохранённое подтверждение полной QA в отчёте, а не проверку PDF сейчас. История не запускает кодирование/растровую проверку заново. Для новой проверки тиража используется ранее добавленный audit. Изменённый после запуска PDF здесь автоматически не перепроверяется.

## Достоверность и границы

Медианы пересчитываются по сырым непрогревочным повторам. Требуются все заявленные замеры, COMPLETE, совпадение количества/формата и сохранённые полные QA PASS для выбранных PDF. Время должно быть конечным/положительным, полная операция не короче производства. Неполные/ошибочные/UNVERIFIED/LIMITED/отменённые варианты не получают успешных медиан. Один повреждённый файл не скрывает остальные; ошибка видна строкой.

Разные запуски, размеры и компьютеры **не объединяются в новый общий рейтинг**. История показывает отдельные сохранённые варианты; источник сборки/CPU/ОС виден в подробностях, полный профиль — в исходном HTML. Общий сравнительный импорт историй с группами сопоставимости остаётся отдельным долгом P07/P08.

Поддержан kind resource-lab/schema1. Старые benchmark/scientific/comparison форматы по-прежнему открываются через прежние отчёты/папки, не выдаются за новый формат. Каталоги сканируются только на одном уровне `lab-*/lab.json`, без рекурсивного обхода соседних проектов. До1000 кандидатов/100 строк индекса; индекс читает суммарно до32МиБ, файлы свыше2МиБ оставляет для явного открытия. При выборе отчёт ограничен32МиБ/4096 вариантами/13 попытками на вариант. Более крупный отчёт предлагается открыть в браузере.

Чтение идёт в существующем собственном worker, с очередью в Tk и кооперативной отменой между чтениями. GUI не блокируется; прежние результаты производственной генерации не заменяются просмотром истории. Пути артефактов должны быть относительными и оставаться внутри запуска после resolve (включая symlink/junction); absolute/drive/`..` отклоняются. История ничего не удаляет и не перезаписывает.

## 12 задач и доказательства

1. Ограниченный read-only индекс выбранной папки.
2. Проверка kind/schema/размеров/структуры и понятные повреждённые строки.
3. Восстановление медиан из сырых повторов, исключение прогрева.
4. Допуск только полных сохранённых QA-подтверждений, без фиктивных победителей.
5. Отдельные аппаратные/программные сведения и отсутствие смешанного рейтинга.
6. Безопасные относительные ссылки и явная недоступность пропавшего PDF.
7. Встроенная тёмная вкладка без JSON и новых окон.
8. Поиск/фильтр/постраничный просмотр без scrollbar.
9. Асинхронное чтение/отмена без замены прошлого результата генерации.
10. Открытие браузера/PDF/папки и интеграция меню.
11. Малые модельные/негативные/Tk проверки и настоящий двухстраничный пример.
12. README/WORK_LOG/контракты/карта долгов, отдельный PR/исходный архив.
