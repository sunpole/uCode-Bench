# P02 — видимая генерация и ранний дизайн

Основа 854126d (P01); ветка codex/modernization-p02-visible. Один комплексный этап. По новой просьбе пользователя выбран видимый набор **12 задач**: 9 пунктов P02 и ранние пункты P10.1–3. Папка готовых PDF реализована; выбор папки временных данных остаётся в P06 вместе с Disk/Hybrid, фиктивной настройки нет. Остальные части большого задания не объявляются готовыми.

## Что изменено для пользователя

- Лёгкая тёмная тема на существующем Tk, контрастный текст, бирюзовый прогресс, компактные кнопки. Новых библиотек/эффектов нет.
- Вкладки «Генерация», «PDF и цвет», «Тесты», «Справка» в одном окне. Настройка геометрии/CMYK и список merger больше не создают Toplevel. Стандартные диалоги выбора файла/папки сохранены.
- Произвольная база 1–10000 и прежние пресеты. Сохраняются отдельные уникальные каталоги; старые базы не заменяются.
- Поле экземпляров и явная политика повторов TXT. По умолчанию сохранены все строки и их порядок. Уникальный режим оставляет первое появление каждого значения. Ведущие нули остаются строковыми данными.
- Предварительная формула: unique × copies для уникального режима, rows × copies для совместимого режима с дубликатами. Повторы научных тестов сюда не входят. Модель считает типы раздельно; реально доступен только QR.
- Один код = одна страница. В режиме «оба» записываются два представления одного тиража: N одностраничных PDF и общий N-страничный. В отчёте логическое число кодов и физические страницы всех файлов разделены.
- Пользователь выбирает папку готовых PDF. Результат по-прежнему создаётся в новом подкаталоге, ничего не перезаписывается.
- Настройки схемы v2: copies, политика повторов, количество новой базы, папка PDF плюс прежние печатные параметры. v1 читается автоматически; старый API сохранения не стирает новые параметры. Есть восстановление стандартных значений.

## Реальное улучшение обработки

Уникальные значения кодируются один раз. Для экземпляров используются те же неизменяемые матрицы в требуемом порядке; PDF writer всё ещё создаёт каждую страницу, QA независимо проверяет каждую записанную страницу. На проверке 2 уникальных × 3 получено **6 настоящих страниц**, но encoder получил **2 значения**. Это подтверждённое сокращение числа кодирований, не утверждение о конкретном проценте ускорения всей операции.

`source-codes.txt` хранит исходные записи, `codes.txt` — фактическую последовательность выходных страниц. Manifest содержит generation/input_records/unique_values/duplicate_records/copies_per_value/codes_per_type/encoding_values_planned/encoded_values/pdf_pages_written. «ОТЧЁТ.txt» объясняет расчёт тиража. После отмены плановые и готовые результаты не смешиваются.

`iter_codes` проверяет TXT по строкам, с чтением не более 4097 байт за раз, BOM/UTF-8/CRLF, номерами ошибок и отменой. Нельзя прочитать огромную строку без ограничения. Совместимый `load_codes` остаётся ограниченным списком. `build_plan` читает максимум 10001 элемент и отклоняет превышение; multiplication проверяется до разворачивания экземпляров и создания папки. Безлимитное потоковое сканирование API не означает безлимитную производственную генерацию: текущий итог до 10000; полная потоковая запись/QA — P06.

## Ограничения и продолжение

Визуальный просмотр тёмного оформления/читаемости на своём экране выполняет пользователь. Шрифт и отступы уменьшены для компактности. Справочный текст внутри своей ограниченной области допускает прокрутку; основной рабочий процесс помещается в окне.

Не добавлены новые кодовые стандарты/движки, multiprocessing, affinity, Disk/Hybrid, график и минимальные режимы. Текущий ReportLab, CMYK K100, размеры, gate и историческая методика сохранены. Реального сравнительного времени ускорения этот патч не заявляет. Следующие технические блоки — P03/P04; остаток временной папки P02.7 связан с P06.

Патч уже находится в текущей тестовой папке и ветке codex/modernization-p02-visible на GitHub. Закройте старое окно и заново запустите Start-uCode.cmd из этой папки. Наличие Python с библиотеками и tkinter проверено тем же runtime probe, который использует launcher; двойной щелчок и открытие внешнего просмотрщика вручную не проверялись.

Для другой рабочей копии используйте ZIP в новую папку. Исходный ZIP сохраняется локально в output/uCode-P02-<commit>.zip; он содержит исходники и документацию, без зависимостей, пользовательских настроек и результатов. Полные PDF/CI evidence остаются отдельно в output/. Старые output и пользовательские TXT сохраняются. Для возврата выбирать ветку P01 при чистом git status либо распаковать её отдельно, не reset/clean и не удаление результатов. Финальный коммит доказательств меняет только документацию и сводку, проверенный код не изменён.
