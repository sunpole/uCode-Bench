# PDF без проверки — 28.10.2026

## Как запустить

Закройте старое окно. Запустите Start-uCode.cmd из тестовой копии `016_uCode_PDF_test`. Внизу рядом с главной кнопкой видны **С проверкой / Без проверки / Частично**. Выберите **Без проверки**. Заголовок и главная кнопка подтвердят режим.

Для обычной работы выберите TXT и нажмите **PDF БЕЗ ПРОВЕРКИ**. Для сравнения во вкладке **Тесты** задайте количество кодов, повторы и ядра, нажмите **ТЕСТЫ БЕЗ ПРОВЕРКИ**. Например, 2000 кодов, 1 и Все, один повтор — два результата. Режим передаётся и в расширенную матрицу **Все параметры…**, и в прогрев, если его включили. По умолчанию полная проверка; выбор сохраняется между запусками.

После записи программа не перечитывает страницы для проверки структур/цвета, не декодирует QR и не создаёт растровые контрольные картинки. Время проверки 0 секунд, в таблице **Выкл.**, результат **СОЗДАНО БЕЗ ПРОВЕРКИ / UNVERIFIED**. 100% означает завершение выбранной операции, не подтверждение качества. PDF/ОТЧЁТ.txt/CSV/HTML и исходные времена сохраняются локально.

**Частично** продолжает проверять структуры и матрицы, но без растровых образцов (LIMITED). **Минимум расходов** уменьшает хеширование/обновления прогресса и другую служебную работу, сам по себе проверку не отключает. Для ещё меньших расходов при генерации можно совместить **Компактный**, **Минимум расходов**, **Без проверки**. Контроль входного TXT/размеров, ограничения RAM/диска, ошибки записи и отмена сохраняются.

**Проверить PDF** запускает отдельный аудит только по нажатию; исходный PDF/manifest не изменяется. **Научный профиль — всегда с проверкой** сохраняет старую методику, три повтора и gates. При выбранном «Без проверки» он не запускается и направляет во вкладку Тесты; скрытого включения QA нет.

## Причина и 10 небольших задач

В прежней реализации production принимал deferred, но лабораторный worker безусловно вызывал run_batch(qa_mode="full"). Настройки PDF не действовали на тестовые запуски.

1. Общие видимые кнопки проверки рядом с запуском, блокировка при работе.
2. Точное название режима в заголовке/кнопке/итоге, сохранение предпочтений.
3. Передача qa_mode из простых и расширенных тестов в LabConfig/request/worker.
4. Реальное исключение PDF QA, включая прогрев, без ложного PASS.
5. Статистика UNVERIFIED/LIMITED только по полным согласованным записям.
6. Отдельные строки/скорости/времена для непроверенных PDF, без проверенного рейтинга.
7. CSV/TXT/HTML с явным охватом, QA=0 и временем выбранной операции.
8. История сохраняет статусы/времена; scientific/CLI не игнорируют просьбу выключить QA.
9. Малые реальные PDF, негативные сценарии данных, Tk-кнопки и геометрия DPI.
10. README/контракты/журнал/PR/исходный архив, сохранение локальных данных.

Также vector сохраняет структурную QA/LIMITED, полные/поддельные/ошибочные записи не подменяют non-full измерения, CLI и отдельный scientific сохраняют контракт.

Финальные 13 проверок после уточнения scope vector и метаданных таймера: **PASS за 5,524 с**, `output/optional-qa-final.log`. Малый сохраняемый пример: `output/no-qa-example-20261028-154935-1132b7/` с двухстраничным PDF и браузерным отчётом одного двухстраничного теста; оба UNVERIFIED, QA=0,0с (`output/optional-qa-example.log`). Полные локальные пути/PID/данные примера не публикуются.

Проверки создали только малые PDF до 7 страниц. Большие 200/1000/2000/10000 серии не запускались; сравнение скорости на двух кодах не экстраполируется. Ручного обхода мышью/скриншотов не выполнялось; визуальная приёмка у пользователя. Новых установок/глобальных настроек нет.

## Повтор и обновление

`python -m unittest discover -s tests -p test_optional_qa.py -v`

CLI: `python -m ucode lab --lab-counts 2 --cpu-counts 1 --backends serial --repeats 1 --qa deferred --mode multipage`. Код завершения 2 означает созданный непроверенный результат, не ошибку записи и не QA PASS. Исторические suite/benchmark не принимают --qa deferred.

Ветка `codex/optional-pdf-verification`, база `codex/button-settings`; main не меняется. Тестовая копия содержит патч сразу. Для другой копии сначала сохраните свои правки и используйте отдельную чистую папку/ветку/исходный ZIP; не накатывайте reset/clean поверх пользовательских данных. TXT/output/.local-state сохранять. Откат исходников — отдельная копия `codex/button-settings`; старые результаты не переписываются.
