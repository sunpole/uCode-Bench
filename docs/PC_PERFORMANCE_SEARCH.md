# Подбор скорости на текущем ПК

Вкладка **Подбор ПК** сравнивает реализованные способы на компьютере программы. Это отдельный пользовательский эксперимент; исторический научный профиль не изменён. Большие тесты запускает пользователь.

## Запуск

1. Закрыть прежнее окно, открыть **Start-uCode.cmd** из тестовой копии `016_uCode_PDF_test`.
2. Открыть **Подбор ПК**. Выбрать тиражи кнопкой, своё число добавить через **Добавить**. Начальный набор: **200 / 1 000 / 10 000 / 100 000**.
3. Задать повторы, желательно **3**. Один повтор — предварительный замер. Прогрева здесь нет; запуск процессов входит во время.
4. **CPU → Физические ядра** и **Все количества CPU этого ПК** проверяют 1, 2, 3 … до доступного числа. Без галочки используются количества из вкладки **Тесты**, например 1 и Все. SMT выбирается отдельно; можно сравнить оба типа.
5. Кнопочными меню выбрать способы кодирования, обычный/компактный PDF, расходы, порции данных, числа частей, создание частей по очереди/одновременно и движки объединения. Поддержан множественный выбор.
6. ОЗУ: **Авто**, **Макс. с резервом**, **Половина**. Это полезные данные в безопасном бюджете, без искусственного заполнения RAM.
7. Рядом с запуском выбрать **С проверкой / Без проверки / Частично**. Минимальные расходы сами QA не выключают.
8. Проверить план, нажать **НАЧАТЬ ПОДБОР**. **Отчёт в браузере** показывает сводку и каждый проход. Файлы остаются в выбранной Папке PDF / `search/pc-*`.

**Отбор + крайние CPU-наборы**: первый размер проверяет все выбранные варианты direct. Далее остаются лучшие K и лучшие варианты на минимальном/максимальном числе CPU каждого способа/типа CPU. Малый тираж не исключает все многопроцессные режимы. Остальные сочетания на больших размерах не проверены, охват указан в отчёте.

**Прямой PDF: все варианты** проверяет всю выбранную direct-матрицу на каждом размере. Предел 4096 относится к числу конфигураций, не страниц.

Разбивка: на каждом размере берётся лучший измеренный direct-профиль для размера/типа CPU и максимальный выбранный CPU-набор. Проверяются выбранные числа частей/способы/движки. Перебор всех остальных профилей разбивки пока не реализован. Число частей ограничивается числом страниц; одну страницу не разбивают.

## Сравнение

Во всех случаях получается **один PDF с теми же кодами в том же порядке**: напрямую либо через части с объединением. Части создаются заново для каждого движка/повтора. Полное время включает подготовку, запуск процессов, кодирование, запись, объединение, выбранную финальную QA и завершение. Части создаются без промежуточной QA, проверяется финальный PDF.

Победитель — медиана фактического `launcher_wall` полного согласованного набора повторов. CSV сохраняет также QR/запись/части/merge/QA, наблюдаемые CPU-секунды/RSS и размеры PDF/каталога. Параллельные QR/write таймеры перекрываются; в распределении полного времени используется wall time создания частей.

**CPU разрешено** — маска, не доказательство полной загрузки. Одновременно частей не больше числа частей и выделенных CPU. Последовательный кодировщик каждой части использует один поток: 10 частей не гарантируют загрузку14 ядер. Merge/QA могут оставаться последовательными. Долгая запись PDF не доказывает, что виноват диск: она включает CPU/сжатие/IO. RSS/CPU наблюдаемые; короткие процессы/пики могут быть пропущены, shared RSS может учитываться повторно.

QA FAIL → INVALID без победы. Без проверки → UNVERIFIED и QA0; частично → LIMITED. Отмена/ошибка/ресурсный предел сохраняют частичный отчёт, неполные повторы не ранжируются. Разница менее5% не доказывает устойчивое превосходство. Рейтинг относится к конкретному тиражу/ПК/профилю/сборке. Отчёты: HTML, CSV, JSON и ОТЧЁТ.txt.

**11 адаптеров, 9 семейств PDF** работают на объединение. Они не заменяют QR-кодировщик: сейчас ReportLab, большие PDF записывает uCode DiskPDF. Недоступные инструменты остаются SKIPPED с причиной.

**Не все возможные способы подключены**: Joblib/loky, Segno, python-qrcode, ZXing-C++, InterpreterPoolExecutor — кандидаты следующих патчей. Каталог различает установлен/подключён. InterpreterPoolExecutor требует Python3.14+, текущий локальный runtime3.12.14. Установка библиотеки не означает готовый адаптер или ускорение.

Источники: [Python](https://docs.python.org/3.14/library/concurrent.futures.html), [Joblib](https://joblib.readthedocs.io/en/latest/parallel.html), [PyMuPDF multiprocessing](https://pymupdf.readthedocs.io/en/latest/recipes-multiprocessing.html), [ZXing-C++](https://github.com/zxing-cpp/zxing-cpp), [Segno](https://segno.readthedocs.io/en/latest/). Общий PDF-документ между потоками не разделяется; части используют отдельные процессы/файлы.

Создана собственная `.venv` тестовой копии: раньше launcher выбирал базовый Python, расширенные зависимости были только в старой папке. Восстановлены проектные Python/npm-пакеты и инструменты, без глобальных установок/PATH/реестра. На другой установке пользователь запускает **Setup-All-Engines.cmd**, скрытого скачивания нет.

Зафиксированы ReportLab4.4.9, pypdf6.21.2, Pillow12.3.0, PyMuPDF2.0, pikepdf10.17.0, pdfrw0.4, pypdfium2 5.14.0; qpdf12.4.2, mutool1.28.5, pdfcpu0.16.3, PDFBox3.0.8, pdf-lib1.17.1, PDFsharp6.2.4. Это не утверждение о новизне/превосходстве. Официальные URL/хеши: installer, requirements, package-lock; точные локальные записи: `tools/python-install-report.json`, `tools/requirements-lock.txt`, `tools/cache-copy-provenance.json`, `tools/pdfsharp/build-provenance.json`. Бинарники/зависимости/личные результаты не коммитятся.

PDFsharp округлял прямоугольник страницы до3 знаков и нарушал прежний допуск0,0003pt. Helper-v2-exact-boxes переносит Media/Crop/Trim/Bleed/Art boxes массивами PdfReal с сохранением точности; контент/CMYK не меняется, QA не ослаблялся. Старую DLL пересобрать штатным installer; probe читает реальный маркер DLL. [Закреплённая версия](https://github.com/empira/PDFsharp/tree/v6.2.4).

## Архитектура и границы

`performance_catalog.py` — probe/семьи/runtime; `pc_search.py` — план/очередь/отбор; `batch_strategies.py` — spawn-части, непересекающиеся CPU-подмножества, порядок, merge/QA; `search_ui.py`, `search_report.py` — кнопки/настройки/отчёты. Используются прежние lab worker, affinity, Windows job/Linux RSS guard, отмена, fingerprint и streaming.

Большие direct-попытки и части используют собственный временный SQLite QR-кэш `.work-*`, удаляемый после закрытия. PDF/коды/индексы/отчёты сохраняются. Общий pypdf reader финального внешнего mergedPDF может хранить метаданные O(N); он под бюджетом процесса, но полностью потоковая QA всех движков не заявлена.

Оценка диска консервативна, не гарантированный верхний предел; проверка ресурсов каждой попытки сохраняется. Merger timeout120s снят только внутри явного поиска, старый scientific сохраняет120s. Без callback — честное ожидание, непрерывный процент не имитируется. Отмена после кооперативного ожидания завершает только собственное дерево. Победитель автоматически не применяется к обычной генерации TXT. Простые тесты с ровно выбранным числом проходов и прежняя история сохранены отдельно.
