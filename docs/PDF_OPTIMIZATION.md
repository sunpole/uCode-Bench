# Оптимизация PDF: отдельный профиль, 28.10.2026

Ветка `codex/pdf-optimization-layer`, основа `5da7689`. Рабочая копия — текущая тестовая папка `016_uCode_PDF_test`. Исходная `016_uCode` не обновляется этим патчем. Старый scientific-профиль, результаты и main сохранены. Новых установок нет.

## Как попробовать без терминала

Закройте старое окно и откройте **Start-uCode.cmd** из этой тестовой копии.

1. Загрузите свой TXT. Во вкладке **PDF и цвет** выберите **Один PDF**, профиль **Компактный** и **Минимум расходов**. Размер/поле/цвет действуют как раньше; по умолчанию QR V1-M, модуль 0,5 мм, поле 4, векторный CMYK K100.
2. Для проверенного результата оставьте **QA: Полная**. Для быстрого производства можно явно выбрать **Отложена**: кнопка и результат содержат **БЕЗ QA**, статус `UNVERIFIED`. Это не подтверждение качества. **Без растра** проверяет все векторные страницы, но даёт `LIMITED`.
3. После создания **Проверить PDF** запускает независимую проверку сохранённого тиража. Её результат лежит в `audits/qa-…/audit.json` и `ОТЧЁТ.txt`; исходный PDF и manifest не перезаписываются. Для старого тиража доступна также CLI-команда `audit` ниже.
4. **Лаборатория → Сравнить PDF (первые)** сравнивает четыре варианта: обычный/компактный × normal/minimal. Берутся первые выбранные количество, CPU, единица CPU, метод и RAM. Число повторов берётся из формы (по умолчанию 3). В лаборатории QA всегда полная независимо от производственной настройки.
5. В **Папке PDF/laboratory/** сохранены PDF и `comparison.html`, CSV, `ОТЧЁТ.txt`, сырые результаты. Есть медиана создания, время с QA, скорость и фактический размер PDF. Парные отношения рассчитываются только при одинаковых CPU/RAM/backend/числе кодов/другом профиле и успешных полных повторах. Значение × меньше 1 означает замедление; отрицательная экономия — увеличение размера.

Для больших 200/500/1000/10000 запускайте сравнение самостоятельно. Полная матрица CPU/RAM × два PDF × два режима расходов может содержать много попыток: число видно до старта. «Первый вариант» остаётся одним вариантом, «Вся выбранная серия» перебирает все выбранные оси последовательно.

## Что оптимизировано (15 задач)

1. Разделены полезная генерация, запись PDF и QA; исторический научный benchmark не заменён новым.
2. Добавлен сохраняемый `PrintSettings.pdf_profile`: `standard` по умолчанию, `compact` по выбору.
3. Добавлен потоковый writer **uCode CompactPDF/1** на стандартной библиотеке; QR по-прежнему кодирует ReportLab.
4. MediaBox/пустые Resources наследуются от общего Pages; цвет, завершающий fill, Creator/Title записаны один раз на документ. Видимых подписей в старом PDF и раньше не было; Title/Creator также были общими.
5. Горизонтальные серии модулей объединяются по вертикали; один составной путь и fill вместо fill на каждой полосе. Данные пути сжаты Flate.
6. Одинаковые матрицы используют один indirect Contents-поток. Уникальные номера требуют собственных контуров; содержимое разных QR не объединяется ошибочно.
7. QA повторно использует уже проверенный идентичный indirect Contents только внутри одного PDF reader. Каждая страница всё равно проверяется на размеры, ресурсы, запрещённые свойства и соответствие ожидаемой матрице/номеру. Уникальные потоки декодируются каждый.
8. `minimal`: более редкие progress/clock updates (не чаще 0,5 с и порог 64 элемента), без SHA-256 файлов и дублирующего source-codes.txt в производстве. codes.txt, manifest, человеческий отчёт, метрики, контроль ввода/порядка/RAM/диска и отмена остаются.
9. Явные режимы `full/vector/deferred` с различимыми COMPLETE/LIMITED/UNVERIFIED. Отключение QA не объявляется ускорением проверенного процесса.
10. Отдельная последующая проверка готового тиража, уникальная папка отчёта, без изменения исходного статуса.
11. Совместимые preferences: старые v1/v2 получают standard/full/normal; новые поля сохраняются локально.
12. Настройки/статусы/справка и кнопка проверки встроены в главное Tk-окно.
13. Лабораторные оси PDF/activity и быстрый запуск четырёх сопоставимых вариантов.
14. Размер PDF и парные отношения времени создания/времени с QA/байт в JSON/CSV/TXT/HTML; нет победителя при QA FAIL.
15. Малые регрессии, скрипт A/B на 7 страницах, Windows/Linux CI и документация. Автоматические большие нагрузки отсутствуют.

## Качество и границы

Компактный PDF остаётся векторным DeviceCMYK; нет растровой подмены, шрифтов, форм, трансформаций или ослабления списка разрешённых PDF-операторов QA. Точность координат 0,00001 pt, допуски прежнего независимого QA сохранены. QR-кодирование, поля и физический размер не сокращаются ради скорости. Новый writer поддерживает только текущий QR V1-M/12 цифр и до 10000 страниц.

Объединённые пути меняют серые пиксели сглаживания на границах: побитовое совпадение PNG не обещается. Малый тест на 1016 dpi подтверждает одинаковую чёрно-белую геометрию после порога 128; отдельные проверки подтверждают матрицы/декодирование/CMYK/размеры. Это не сертификация пробной печати или сканера. PDF/X не сертифицирован.

При полной QA проверяются все векторные страницы, растровое декодирование — первая/средняя/последняя. При отсутствии Poppler результат LIMITED; ошибка проверки INVALID. QA-кэш не переносится между файлами/запусками и не заменяет проверку другой страницы только по номеру или payload.

Минимальный режим не означает нулевые расходы: контроль безопасности, отчёты, RAM/CPU монитор лаборатории и отмена обязательны. Одностраничные файлы не могут делить объекты между разными PDF; общий документ экономнее по служебным структурам. Кодирование может быть process/thread, запись PDF/QA пока последовательны. Все матрицы до записи остаются в RAM. Перенос PDF на физический диск через fsync не измеряется. Автоматического выбора победителя для производства нет.

Windows/Linux CI настроен, его успешность до получения результата не заявляется. Крупные скорости и проценты экономии этим патчем пока не измерены, визуальная приёмка пользовательская.

При желании из корня этой копии с доступным Python/Poppler:

```powershell
python -m unittest discover -s tests -v
python scripts/verify_pdf_optimization.py
# Реальные 7 страниц × 4 профиля × 3 повтора; уникальная output/optimization-smoke/…
python -m ucode lab --lab-counts 200 --cpu-counts 1 --backends serial --ram-modes max --pdf-profiles standard,compact --activity-modes normal,minimal
python -m ucode generate --input codes.txt --mode multipage --pdf-profile compact --activity minimal --qa deferred
python -m ucode audit --input "output/jobs/pdf-N-…"
```

`generate` с LIMITED/UNVERIFIED возвращает код 2, COMPLETE — 0; это намеренное отличие от успешной полной проверки. Результаты пишутся в новые каталоги, старые не удаляются. Обновление: используйте эту рабочую ветку/исходный ZIP в отдельной папке, не reset/clean поверх локальных правок. Откат режима: Обычный + Полная QA + выключить Минимум расходов либо «Стандартные настройки». Пользовательские TXT/output не удаляются.
