# Несколько процессов на каждом выбранном ядре

Патч codex/processes-per-core от PR20. Добавляет новый параметр конвейера, не меняет обычную генерацию и исторический научный профиль.

После завершения своих тестов перезапустить Start-uCode.cmd тестовой копии. В **Тесты → Конвейер → Процессов на ядро** можно выбрать несколько значений от 1 до 10. Консоль использует тот же параметр:

```text
test pipeline --codes 10000 --split cores:14+0 --processes-per-core 1,2,5,10 --schedule queue --batch 32 --repeats 2 --metrics cpu --ram max --pdf compact --qa off --xy on
```

На ПК с 14 доступными физическими ядрами план: 14 / 28 / 70 / 140 исполнительных процессов, четыре варианта по два повтора, **8 запланированных прогонов**. Большой тест автоматически не выполнялся. До запуска выбрать «Проверить», затем выполнить команду. Замеры загрузки CPU и график XY включены, проверка PDF выключена — результаты UNVERIFIED.

## Что именно сравнивается

Множитель не добавляет вычислительные ядра. Сохраняется тот же выбранный набор CPU; каждому CPU назначаются1/2/5/10 процессов с подтверждённой affinity. Физический профиль использует по одному логическому CPU каждого физического ядра, как победивший14+0. Два процесса на этом CPU делят его время; это другой эксперимент, чем28процессов на28SMT с маской обоих потоков ядра. При выборе SMT параметр означает число процессов на каждый выбранный логическийCPU.

При14+0 каждый исполнитель делает QR и геометрию/сжатие страницы. При разделении QR+PDF множитель применяется к обоим пулам. Окончательный сборщик остаётся одним и разделяет выбранные CPU. Служебные GUI/контроллер/сборщик не включаются в число исполнителей.

Общая очередь выдаёт небольшую следующую порцию освободившемуся процессу. Равные части делятся уже между фактическими процессами, с сохранением ограниченных пакетов. Все исполнители должны подтвердить готовность перед первой порцией; процессы с нулём обработанных страниц не выдаются за использованные.

Отчёт сохраняет множитель, выбранныеCPU, запрошенные/подтверждённые/обработавшие страницы процессы, PID/affinity, число страниц и порций каждого процесса, секунды, CPU/RSS, модель памяти, XY. В HTML/графиках/архиве/XY множители различимы. CPU одного выбранного процессора суммирует все закреплённые за ним процессы; дополнительные PID не превращаются в дополнительные ядра.

## Память и допуск

Множитель1 сохраняет прежнюю консервативную оценку128МиБ на исполнителя. При множителе>1 сначала проверяется нижняя оценка48МиБ на процесс. Затем запускается первый **реальный исполнитель будущего пула**: он импортирует движок, сообщает собственные RSS/private, но ещё не создаёт QR/PDF. Весь остальной пул допускается по оценке:

`256МиБ родитель + процессы × max(48МиБ,1,5×измеренная база) + ограниченные пакеты ×40000байт`.

Если наблюдение памяти недоступно, используется128МиБ. Это оценка с запасом, не измеренный пик и не гарантия потребления; её поля различают минимум, измеренную базу и fallback. Первый процесс не создаётся заново после допуска, участвует в работе и учитывается в таймере. Это не скрытый прогрев кодов.

Резерв ОС, sampled RSS-guard и Windows Job на commit дерева не ослаблены. Проверка свободнойRAM продолжается во время старта и работы. Если план не помещается, вариант получает отказ с причиной и не считается успешным/быстрым. После отказа пробный процесс завершается. Для140процессов может понадобиться больше свободнойRAM, чем есть в текущий момент. ОЗУ искусственно не заполняется. До256исполнителей на вариант; превышение явноSKIPPED. На Linux остаётся sampled/cooperative защита, не kernel quota.

Время включает запуск всех процессов, калибровку, работу, выбраннуюQA и завершение. Дополнительные процессы могут оказаться медленнее из-за старта, переключений, IPC и памяти. Два повтора — предварительное сравнение; ускорение заранее не обещается. Сравнение CPU-диагностики ВКЛ/ВЫКЛ удваивает число прогонов, поэтому в пользовательской команде выбран толькоcpu.
