# M08: границы и независимость проверки качества

Дата сверки источников: 2026-10-27. Кодировщик — ReportLab. Модуль
`ucode/qrdecode.py` не импортирует кодировщик и извлекает данные непосредственно
из модулей QR. Это узкий проверяющий декодер первого эксперимента, а не готовый
универсальный сканер.

## Поддерживаемый контракт

- Обычный QR Version 1, матрица 21×21, уровень коррекции M.
- Один numeric-сегмент ровно из 12 ASCII-цифр; ведущие нули сохраняются.
- Нормальная ориентация, без перспективы, размытия и исправления повреждений.
- Проверяются три finder-паттерна с белыми разделителями, timing-паттерны и
  фиксированный тёмный модуль.
- Обе копии format information должны совпадать и иметь точный BCH-код;
  допускаются все восемь стандартных масок, уровень M должен быть указан явно.
- Из зигзагообразного обхода извлекаются 26 кодовых слов. Для V1/M это один
  блок: 16 слов данных и 10 слов Reed–Solomon.
- Все десять синдромов Reed–Solomon должны быть нулевыми. Ошибки обнаруживаются,
  но не исправляются. Проверяются numeric-данные, нулевой terminator/alignment
  и оставшиеся pad-слова.

## PDF и фактический рендер

Каждая страница разбирается через pypdf. Проверяются число страниц, все page
boxes, отсутствие поворота, размер модуля 0,5 мм и поля 4 модуля. Разрешены
только залитые векторные прямоугольники DeviceCMYK (0,0,0,1). Из их координат
восстанавливается вся матрица. Она сравнивается с ожидаемым кадром, независимо
декодируется и сверяется с ожидаемым номером.

Прямоугольники допускают погрешность сериализации координат 0,0003 pt.
Матрицы `cm` должны быть точно единичными: погрешность для них не применяется,
поскольку множество малых преобразований накапливается. RGB, grayscale,
растры, формы, аннотации, прозрачность, page `/Group`, текстовые show-операторы
и неизвестные операторы отклоняются. Пустая настройка шрифта ReportLab
разрешена, поскольку не рисует текст.

Контрольные страницы — первая, средняя и последняя — дополнительно рендерятся
из готового PDF через `pdftoppm` при 1016 dpi. Pillow извлекает сетку модулей
из PNG; тот же независимый декодер читает её. Растеризация используется только
для QA и не изменяет векторный PDF. PNG сохраняются рядом как доказательства.
Для набора одностраничных PDF аналогично рендерятся три контрольных файла;
структурно проверяется каждый файл. При отсутствии рендерера или сбое
декодирования проверка, требующая рендер, возвращает FAIL.

`render_samples=False` предназначен для структурных тестов и отдельных файлов
внутри набора; этот флаг явно отражён в результате. Проверка итогового PDF
бенчмарка вызывается с рендером по умолчанию.

Физическая печать, считывание камерой/внешним сканером, PDF/X-сертификация,
произвольные QR-версии и режимы кодирования этим этапом не подтверждаются.
Текущие положительные тестовые символы создаются ReportLab; внешний
предварительно опубликованный эталонный символ пока не включён. Независимость
алгоритма дополнительно проверена чтением первичных исходников ZXing ниже.

## Первичные источники для независимой сверки

- [ISO 32000-1:2008, опубликованный Adobe](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf), §11.7.2: цвета объектов преобразуются в blending colour space transparency-группы. Поэтому одного оператора `k` недостаточно для гарантии отсутствия RGB-конверсии при наличии page `/Group`.
- [ZXing BitMatrixParser](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/decoder/BitMatrixParser.java): расположение format information и обход кодовых слов парами столбцов с пропуском функциональных модулей.
- [ZXing Version](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/decoder/Version.java): функциональные области и таблица V1/M — один блок из 16 слов данных и 10 слов коррекции.
- [ZXing DataMask](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/decoder/DataMask.java): формулы всех восьми масок, где первый индекс — строка.
- [ZXing FormatInformation](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/decoder/FormatInformation.java): маска формата 0x5412 и таблица допустимых BCH-слов.
- [ZXing ErrorCorrectionLevel](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/decoder/ErrorCorrectionLevel.java): уровень M представлен двумя битами 00.
- [ZXing GenericGF](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/common/reedsolomon/GenericGF.java): поле GF(256) с полиномом 0x11D и generator base 0.
- [ZXing ReedSolomonDecoder](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/common/reedsolomon/ReedSolomonDecoder.java): нулевые значения полинома на последовательных степенях примитивного элемента означают отсутствие обнаруженных ошибок.
- [ZXing DecodedBitStreamParser](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/decoder/DecodedBitStreamParser.java): numeric-сегмент читает три цифры из десяти бит, значения 1000 и выше недопустимы.

Ссылки ведут на изменяемую ветку master; при расширении декодера сверку нужно
повторить и добавить независимые эталонные символы для новых режимов.
