# uCode — архив обсуждения QR переменной длины (НЕ ЗАДАЧА)

Дата: 2026-10-30. Статус: **ОТКЛОНЕНО К РЕАЛИЗАЦИИ НА ТЕКУЩЕМ ЭТАПЕ / АРХИВ ОБСУЖДЕНИЯ**.

**Решение пользователя 30.10.2026:** идея числовых QR разной длины сейчас не имеет практической потребности. Реализацию **не начинать**, исключить из активного бэклога и ближайших версий. Оставить только как обсуждавшуюся гипотезу **в самом конце архива идей**, без назначения сроков, приоритета, исполнителя или версии. Вернуться к вопросу можно только по новому явному запросу пользователя. Это решение не отменяет уже реализованный в 0.3.4 режим отдельного QR с произвольным содержимым; существующий массовый 12-значный QR не меняем.
База: ветка `codex/portable-wip-20261030` (проверенный Windows preview 0.3.4).
История вопроса: при проверке GUI/EXE обсуждалась возможность числовых QR не только из 12 цифр и массовой генерации с разной длиной номера. Пользователь уточнил, что потребности в этой функции нет, поэтому дальнейшая разработка отклонена.

## Подтверждённая архитектура

- Текущий массовый числовой путь `ucode/generators.py::QRGenerator.validate()` принимает **строго 12 ASCII цифр**; `ucode/operator_models.py::SequenceSpec` генерирует строки с padding до 12 и отсечением >999999999999. `ucode/batch.py::iter_codes()` и `SourceIndex` также наследуют эту проверку.
- Другой, **уже действующий** путь `ucode/qr_content_codec.py::encode_content()` поддерживает обычный QR Model 2 V1–V40 с автоподбором версии, сегментами numeric/alphanumeric/UTF-8, L/M/Q/H; `docs/STATIC_QR_V034.md` описывает одиночное содержимое QR, повторные копии и независимую QA. Это не массовый числовой pipeline для списка разных значений.
- Исторический научный benchmark сохраняет неизменный сценарий: QR V1 / numeric 12 / ECC M / модуль 0,5 мм / поле 4 модуля. Его прошлые измерения и проверочные входные данные нельзя менять без новой версии методики.
- Вместимость стандартного QR Model 2 зависит от коррекции: V1 L/M/Q/H = 41/34/27/17 десятичных цифр; V40 = 7089/5596/3993/3057. Официальный источник: https://www.qrcode.com/en/about/version.html.
- Длина числа *не равна количеству кодов*, а количество экземпляров каждого значения — отдельное поле.

## Исторические варианты, рассмотренные в обсуждении (НЕ В ОЧЕРЕДИ РЕАЛИЗАЦИИ)

### QR-L01 — UX и модель входных данных (обсуждение; не утверждено)
- В интерфейсе разделить **«Числовой QR — массовая генерация»** и **«QR — одно содержимое»**; научный профиль — отдельный явно обозначенный пресет.
- В массовом режиме выбрать **«Длина: авто из TXT / фиксированная N»**, `N` целое и проверяется по выбранной коррекции/версии. Для встроенного генератора: количество записей, начальная строка, шаг, дополнение ведущими нулями **только по отдельному запросу**.
- Пример: 00001234, 123456789012, 12345678901234567890 — это строки, не машинные integer; при экспорте и сортировке нельзя терять ведущие нули.
- Не путать «количество значений», «цифр в значении», «экземпляров каждого значения», «итого QR» и «страниц PDF». Показать понятную оценку до старта.

### QR-L02 — универсальный числовой encoder и пределы (обсуждение; не утверждено)
- Для *нового* режима переиспользовать `encode_content` и общий формат QRFrame при максимально возможной совместимости, не копировать таблицы и RS алгоритмы.
- Проверять каждое значение: ASCII цифры, непустое, длина/вместимость по фактическому ECC; автоматический выбор минимальной допустимой версии V1–V40, без незаметного укорочения и удаления нулей.
- В будущих потоковых/параллельных исполнителях сохранить безопасные границы памяти и падение с явной ошибкой для неподдерживаемого пути, не объявлять поддержку до доказанных тестов.
- Версия PDF/физическая геометрия рассчитываются **для каждого конкретного QR**: `modules=17+4*version`, бумага (в модулях) `modules+2*quiet_zone`. При фиксированном модуле рост версии увеличивает печатный размер, не уменьшает модуль автоматически.

### QR-L03 — TXT, генератор, пакетный PDF (обсуждение; не утверждено)
- TXT: одна числовая строка на запись, различная длина допустима в авто-режиме; поддерживать UTF-8 вход, точный исходный порядок/повторы, отчет по каждому элементу без неявных дублей и пропусков.
- Фиксированный режим N: каждая строка имеет **точно N цифр**; конфликт N/фактической длины → явная ошибка с номером строки.
- Генератор последовательности: `N`, старт, шаг, количества, переполнение ёмкости проверять до запуска; leading zero padding — явная настройка; безопасные случаи 1/8/12/20/50/100 символов, и граничные числа.
- PDF: для разных версий QR в одном многостраничном PDF сохранить **индивидуальные размеры страниц** либо добавить явную опцию фиксированного размера страницы с центровкой и неуменьшением модуля; не искажать QR. Separate PDF/merged PDF/both, SVG/PNG только там, где действительно поддерживаются.
- Для сканера/полиграфии сохранять точную геометрию и отчёт CMYK DeviceCMYK 0/0/0/100; не выдавать файл за PDF/X без OutputIntent/ICC.

### QR-L04 — QA, измерения, совместимость (обсуждение; не утверждено)
- Юнит-тесты для разных длин, ведущих нулей, границ ECC и V40, правильных версий, UTF-8 CSV/TXT, опасных ошибочных строк, порядка, отмены и восстановления после перезапуска.
- Малые реальные PDF с 1–7 строками на Windows/Linux, процесс/последовательный режим там, где подтвержден, и сравнение с независимым QR decoder; фиксировать `COMPLETE / LIMITED / UNVERIFIED / INVALID` по действующей методике.
- Отдельно сравнить скорость длинных QR с 12-цифровым baseline. **Нельзя объявлять длинный QR эквивалентным научному QR V1** — меняются количество модулей, PDF/QA и нагрузка.

## Выпуск и риски

- Ветка изменений/PR отдельно от `main`; до нового кода не изменять стабильные `v0.3.0` или предложенный `v0.3.4`. Последний успешный portable preview: https://github.com/sunpole/uCode-Bench/actions/runs/41062786014.
- Для 0.3.4 отдельно остаются: чистая установка/подпись/проверки GUI Windows, Linux/macOS; подтверждённый релиз/порядок слияния; безопасный updater через GitHub с сохранением данных и откатом.
- Для общего бэклога P01–P11 — `docs/MODERNIZATION_PATCHES.md`: нереализованные EAN13/Code128/Data Matrix, движки и лицензии P03, RAM/Disk/Hybrid P06, живой XY P09, завершающая интеграция P11.
- **Нет запланированной версии.** В частности, 0.3.5 не резервируется под переменную длину QR. Любая реализация требует нового решения пользователя; до него идея остаётся только в архиве.
