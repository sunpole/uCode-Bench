# Отчёты вместо накопления PDF: политика тестов uCode

Дата решения пользователя: **2026-10-30**. Статус: **частично реализовано в PR #30, в основном `main` ещё не выпущено**.

## Цель и уточнение границ

PDF для лаборатории — **временный проверяемый артефакт**, а не результат, нужный пользователю для постоянного хранения. Требуется точное измерение цикла кодирование → PDF → сохранение на диск (включая реальные байты и время) → QA, а затем удаление временных PDF **вне временного окна измерения**, чтобы не искажать производительность.

Результатом теста являются: статус PASS/LIMITED/INVALID/ERROR, настройки теста, размеры кода, число кодов/страниц, реальное время, скорость, CPU/RAM/диск, контрольные суммы, QC, ошибки и версии движков; сохранять небольшие **JSON, HTML, TXT**, CSV-телеметрию без личных данных, если применимо.

**Обычная команда «Создать PDF» остаётся производственной функцией:** если пользователь явно заказывает PDF для печати, его нельзя удалять фоновым сборщиком тестов. У пользователя должен быть выбор папки и предохранитель от недостатка свободного места. Автоматических uploads на GitHub нет.

## Реализация PR #30

- `ucode/test_retention.py` удаляет только обычные файлы с расширением `.pdf` внутри **нового изолированного каталога завершённого trial**. Не переходит по symlink и не трогает соседние папки, источники TXT, отчёты или установленное приложение. В результат записывается число/сумма удалённых байтов и состояние очистки; ошибки отделены от результатов QA.
- `ucode/resource_lab.py::_run_trial(..., report_only=True)` вызывает очистку **после завершения дочернего процесса и записи его trial.json** и сохраняет статус retention в trial.json. Время генерации/QA не включает удаление.
- `operator_test_worker.py` включает `report_only=True` по умолчанию для GUI `LabConfig`, `PipelineConfig`, `SearchConfig`. Соответствующие `run_lab/run_pipeline_lab/run_search` позволяют передать флаг; прямые вызовы с `False` остаются совместимыми.
- `tests/test_report_only_retention.py` проверяет удаление пробных PDF, сохранение отчётов и защиту соседних файлов/символических ссылок.
- Пока **НЕ распространяется** на legacy/scientific и консольный сценарий: `load_qualifying_methods` требует сохранённые предыдущие PDF и повторный SHA-256 для допуска к масштабу 1000/10000. Нельзя незаметно ослаблять эту проверку и объявлять PASS после удаления без нового строгого контракта аудита.
- **НЕ чистит существующие 20 ГБ на ПК пользователя.** Для старых `output/jobs` нужен отдельный локальный просматриваемый список/пользовательское подтверждение: только готовые PDF, без удаления отчётов, TXT, настроек и резервных копий.

## QA для полного перехода к report-only

1. Провести реальный GUI-запуск одного test trial, проверить: вектор/растровая QA завершились **до удаления**, производительность до cleanup, нет оставшихся PDF в trial, `trial.json` и сводные отчёты читаются.
2. Проверить многоэтапные pipeline/split/merge; временные исходные PDF нужны до завершения именно этого trial. Очистка после его завершения, не между стадиями.
3. Научный тест — пересмотреть допуск по cryptographic evidence, уже записанным в manifest и QA, с противодействием подделке/устаревшим отчётам; не повышать ранги при частичном/невыполненном QA.
4. Консольная лаборатория и старые archived run должны иметь явную политику хранения, без удаления пользовательских PDF.
5. При Cancel/ERROR сохранить компактный отчет об ошибке даже если временный PDF удалён; не подменять реальный QA статус.
6. Повторять тесты с нехваткой места, запретом удаления, параллельными процессами и антивирусными lock, не закрывать ошибку `retention.PARTIAL`.
7. Добавить явный UI «Тесты: только отчёты» (по умолчанию) и отдельную опцию сохранения доказательственного PDF только по прямому выбору пользователя, если это действительно необходимо.
