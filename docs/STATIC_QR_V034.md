# 0.3.4 — статическое содержимое QR без сервера

Ветка `codex/v034-local-qr-content`. Новых зависимостей нет. Рабочие ReportLab, pypdf и Pillow уже были в проекте. Исходный утверждённый макет не изменяется, используются его вкладки и акценты. Запуск: `Start-uCode.cmd`; запасные browser/legacy launcher сохраняются. Новый редактор доступен в основном HTML-интерфейсе, прежний Tkinter остаётся прежним.

## Создать и сравнить

1. «Тип» → выбрать QR → «База» → **«Данные QR»**.
2. Выбрать вид содержимого, заполнить поля, нажать **«Использовать данные»**. Ошибки не заменяют прежний источник.
3. В «Пути» проверить имя/папку и подтвердить. В «Оформлении» выбрать L/M/Q/H, размер модуля, поле, цвет/подложку. Матрица и страница растут автоматически, размер модуля сохраняется.
4. «Просмотр» → «Создать PDF». Для полноценной проверки выбрать «С проверкой»; без неё итог UNVERIFIED. Для одиночного содержимого работает один процесс, настройка ядер относится к массовым TXT.
5. В папке результата есть PDF, PNG без сглаживания (10 пикселей на модуль), векторный SVG и точные UTF-8 байты `payload.txt`. Из «Другого» можно открыть PNG, SVG и содержимое.
6. На другом сервисе указать те же поля, коррекцию и размер. Для точного побайтового сравнения использовать там режим «Текст» и вставить **«Скопировать содержимое»** из uCode: vCard/событие могут иметь разные служебные поля у разных генераторов.

Разные корректные QR одного текста могут выглядеть по-разному из-за выбранной маски, кодирования сегментов, ECI, версии или сериализации полей. Проверять нужно считанное содержимое и действие телефона, а не совпадение рисунка. Для плотных QR открыть PNG в большем размере или распечатать PDF; маленький экранный preview может быть недостаточен для камеры.

## Реальные виды содержимого

| Вид | Что кодируется |
|---|---|
| Текст | Текст, переносы, кириллица, emoji |
| Ссылка | Готовый HTTP/HTTPS URI; IDN и не-ASCII путь нормализуются |
| E-mail | mailto, получатель, percent-encoded тема/сообщение |
| Телефон | tel: с номером |
| SMS | SMSTO:номер:сообщение |
| Контакт | vCard 3.0: имя/фамилия, телефон, email, организация, должность, сайт, адрес, примечание |
| Wi-Fi | WIFI:T/S/P/H, WPA/WPA2 Personal, WEP либо открытая сеть; экранирование специальных символов |
| WhatsApp | Готовая wa.me ссылка, номер и сообщение |
| Событие | iCalendar/VEVENT, местное время, UID, DTSTAMP, начало/окончание, место/описание |
| Координаты | geo:широта,долгота |
| PDF, изображения, видео, приложение, соцсеть | Готовая ссылка пользователя; файлы и страницы не создаются и никуда не загружаются |

Все эти QR статические. Для чтения текста/контакта/Wi-Fi интернет не нужен; открытие внешних ссылок, звонок, отправка сообщения и WhatsApp зависят от соответствующего сервиса/связи. Телефон не обязан автоматически выполнить действие: это решает его камера/сканер. Соцсеть — один существующий профиль/страница, приложение — одна готовая ссылка, без собственного сервера перенаправлений. «2D Barcode» на чужом сайте — категория кодов, а не ещё один формат содержимого. EAN/Code128/Data Matrix/iQR остаются будущими модулями.

Wi-Fi пароль и контактные данные находятся в QR в открытом виде. Они сохраняются локально в источнике/manifest/payload.txt. Текстовый архив исключает поле payload и не копирует исходные файлы или картинки; production.html также не содержит payload. Автоматической отправки данных нет.

## Кодирование и проверка

- `qr_payloads`: валидируемые форматы, URI-экранирование, UTF-8 line folding, защита от внедрения строк в однострочные поля; PayloadSource совместим с SourceInfo/подсчётом тиража и восстановлением источника.
- `qr_content_codec`: обычный QR Model 2, версии 1–40, L/M/Q/H. Числа и подходящий алфавит кодируются компактными сегментами; остальной текст — UTF-8, с явным ECI26 для не-ASCII. Реальная вместимость зависит от уровня; переполнение отклоняется до смены источника/генерации.
- Независимый verifier не импортирует encoder. Проверяет обе копии format BCH, version BCH, фиксированные паттерны, маску, remainder bits, deinterleaving RS blocks, все RS syndromes, сегменты, UTF-8 ECI и canonical padding. Таблицы математических параметров QR записаны отдельно в assets/qr-standard-tables.json (данные спецификации, транскрибированы из ReportLab4.4.9 qrencoder; не вызовы encoder для QA).
- `qr_content_job`: отдельная локальная ветка worker, ReportLab vector CMYK PDF; стандартный профиль пишет клетки, compact объединяет горизонтальные серии. Старые числовые pipeline/benchmark не переписаны. Существующий строгий PDF parser извлекает фактическую матрицу и проверяет её независимым декодером; при полной QA Poppler рендерит PDF, затем декодируются реальные PNG. Размер растровой выборки ограничен примерно десятью пикселями на модуль.
- PNG/SVG — дополнительные экспортные форматы. Цвет экрана RGB приблизительно соответствует CMYK, PDF остаётся печатным CMYK. Поиск и preview используют один исходный payload; матрица кешируется с учётом уровня. Один источник может печататься экземплярами в прежних трёх режимах, до 10 000 экземпляров для нового одиночного содержимого.

## Проверено и что остаётся пользователю

`tests/test_qr_content.py`: все 15 видов × 4 коррекции с точным независимым считыванием, большие матрицы до V40 и UTF-8, повреждения и переполнение, невалидные поля, настоящие PDF для каждого вида, PNG-декодирование, повторный audit, все режимы вывода, восстановление источника и отсутствие содержимого в текстовом архиве.

49 целевых тестов новых/прежних QR, quality, operator_web/order_flow/desktop, batch/streaming прошли; после уточнения writer повторно прошли 4 новых теста. Реальная WebView2 `scripts/desktop_smoke.py --order-flow --content`: форма с кириллицей → путь → оформление → PDF1, размеры окна, вкладки, повторный запуск и закрытие. Отдельный малый PDF кириллица+emoji H: полная QA с Poppler дала COMPLETE. Это не тест камеры телефона и не визуальная DPI-приёмка.

Пользователю: проверить камеру телефона на тексте/ссылке/контакте/Wi-Fi/SMS/событии; сравнить считанные значения с payload.txt и другим генератором; проверить оформление в обычном/минимальном окне и Windows100/125/150%. Не подтверждены действия приложений iOS/Android, реальные Wi-Fi подключения, камеры/повреждения, чистая установка и большие нагрузки.
