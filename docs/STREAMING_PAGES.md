# Тиражи без пользовательского максимума10000 — 28.10.2026

## Работа

Перезапустите Start-uCode.cmd из тестовой копии. В обычной генерации можно загрузить TXT больше10000 строк, задать большое число экземпляров или создать большой TXT. Во вкладке Тесты задайте своё количество; фиксированный максимум10000 снят также с настроек и истории. QR по-прежнему ровно12 ASCII-цифр в строке, UTF-8/BOM, порядок/нули/повторы сохраняются.

Для сравнения1 и14 ядер: **Ядра процессора**, галочки **1** и **Все (14)**, один повтор. Два CPU-набора дают два реальных запуска и две строки времени; QA и создание измеряются отдельно. На другом ПК число в «Все» определяется по его физическим ядрам. Нет обещания14-кратного ускорения: PDF/QA последовательны. **Без проверки** действительно пропускает QA, результат UNVERIFIED.

## 13 задач патча

1. Положительные пользовательские counts/copies вместо максимума10000 в UI/CLI/preferences/custom lab/history.
2. Построчная проверка больших TXT и дисковый unique-индекс, без списка всей базы.
3. CountPlan/DiskPlan: уникальность, порядок, экземпляры и итог без разворачивания в RAM.
4. Bounded FrameStore для serial/process/thread; один пул на запуск, принятые партии сохраняются на диске.
5. Потоковый PDF writer, page/xref offsets в SQLite вместо больших списков.
6. Компактные контуры и дисковое повторное использование одинакового QR Contents.
7. Независимая проверка actual final xref/trailer/page tree и каждой матрицы/геометрии/CMYK, bounded reader.
8. Сохранённые full/vector/deferred и отдельный аудит с новыми эталонами, без изменения исходных результатов.
9. Preflight места/памяти и runtime резервов, отмена/частичные файлы без ложного PASS.
10. Шаблоны и lab TXT записываются строками; снят скрытый часовой timeout custom lab.
11. Все пользовательские входы направляются в потоковый путь; большой source остаётся потоковым даже при малом unique-итоге.
12. Малые PDF/негативные сценарии/UI/core masks и совместимость научного профиля.
13. Документация, отдельная ветка/PR/исходный архив и безопасное обновление.

## Архитектура и измерения

Порог10000 выбирает старый быстрый in-memory путь или новый DiskPDF; это не отказ по количеству. Большой source определяется по валидированной сводке, большой итог — после экземпляров. `data.sqlite` хранит строки/уникальные матрицы; `pdf-index.sqlite` — offsets/page refs/content reuse. SQLite cache фиксирован; encoder держит не более выбранных одновременных партий. Нет накопления всех результатов IPC/QA/страниц в Python. Внутренние совместимые load_codes/build_plan list APIs всё ещё ограничены; пользовательские входы используют inspect_codes/CountPlan.

QR кодирует ReportLab. Для больших PDF writer — **uCode DiskPDF/1**, явно указан в print.pdf_writer; это не время ReportLab Canvas и не доказательство самого быстрого движка. Standard пишет обычные контуры, compact объединяет их и переиспользует Contents одинаковых кодов. Малые прежние PDF/научная методика не заменены. Структуры большого PDF проверяются pypdf по одному объекту через сохранённый дисковый индекс; существующий независимый QR decoder и растровые образцы сохранены. Повреждение actual page tree/xref не получает PASS даже при целых индексах.

Оценка места консервативна (16000 байт на код, не измеренный размер). RAM оценена для активных партий; runtime guard проверяет свободную RAM и диск, lab сохраняет прежний собственный Windows job/RSS guard. Одновременно заполнять RAM искусственно программа не пытается. Точное исполнение новых больших тиражей/скорость/пик памяти пока пользовательские измерения.
