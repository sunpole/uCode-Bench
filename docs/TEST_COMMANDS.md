# uCode — команды тестов, язык версии 1

**Конвейер:** добавлен `--processes-per-core 1,2,5,10` (по умолчанию1). Число исполнителей на каждом выбранном CPU, отдельная ось матрицы. Не путать с числом ядер/SMT и размером порции. На14ядрах с2повторами —8 запланированных запусков. [Готовая команда и границы RAM](PROCESSES_PER_CORE.md).

**XY:** у `test lab`, `test pipeline`, `test search` добавлен `--xy on|off` (по умолчанию off). Записывает фактический временной ряд для кнопки **XY: ход работы** в отчёте; тайминги/статусы QA остаются фактическими. Научный профиль не принимает этот флаг. [Шкалы, расходы и ограничения](XY_REPORTS.md), [готовые 12 измерений по результатам подбора ПК](PC_SEARCH_20261029_ANALYSIS.md).

Команды можно попросить подготовить ИИ, вставить во вкладку **Тесты → Консоль**, нажать **Проверить**, затем **ЗАПУСТИТЬ КОМАНДЫ**. Это встроенный язык uCode: команды вызывают те же функции и конфигурации, что переключатели программы. Python, CMD, PowerShell и произвольные программы здесь не выполняются.

Одна строка — одна команда. Несколько строк выполняются по очереди. Пустые строки и строки, начинающиеся с `#`, пропускаются. Перед первым запуском проверяются все строки. При ошибке/неполном результате/отмене следующие команды не выполняются; уже созданные файлы сохраняются. Максимум32 команды в очереди, до64 значений параметра и до4096 конфигураций в одной матрице. Большое число прогонов не скрывается: перед запуском отображается план. У staged-поиска и научного допуска это верхняя оценка, а не обещание точного числа попыток.

**В консоль →** на странице параметров переносит текущие переключатели в полную команду. **Показать кнопками** применяет одну команду обратно к соответствующей странице. Кнопка **Файл** сохраняет/загружает TXT с командами. Последний запущенный текст запоминается; исполнение при открытии программы не начинается автоматически.

## Примеры для вставки

2000 кодов: один проход на1 физическом ядре и один на всех доступных физических ядрах — ровно2 измеренных результата, без прогрева:

```text
test lab --codes 2000 --unit cores --cpu 1,all --backend process --repeats 1 --warmups 0 --batch 32 --files multipage --pdf compact --activity minimal --metrics off --qa off
```

10000 кодов на2,4,12 ядрах, каждый вариант10 раз —30 измеренных результатов:

```text
test lab --codes 10000 --unit cores --cpu 2,4,12 --backend process --repeats 10 --warmups 0 --batch 32 --metrics off --qa off
```

12+2 физических ядра против24+4 потоков SMT, равные части и очередь, по3 повтора —12 результатов на каждый тираж:

```text
test pipeline --codes 1000,10000 --split cores:12+2,smt:24+4 --schedule equal,queue --batch 32 --repeats 3 --metrics off --ram max --pdf compact --qa off
```

Добавить полный цикл14/28, разные порции и сравнение стоимости CPU-замеров (большая матрица — сначала посмотрите план):

```text
test pipeline --codes 200,1000,10000,100000 --split cores:12+2,smt:24+4,cores:14+0,smt:28+0 --schedule equal,queue --batch 8,32,128 --repeats 3 --metrics off,cpu --ram max --pdf compact --qa off
```

Точный выбранный перебор прямой генерации и разбиения с двумя движками объединения:

```text
test search --codes 200,1000 --unit cores,smt --cpu 1,all --each-cpu off --backend process --batch 32 --pdf standard,compact --activity minimal --ram auto --metrics off --search full --keep-best 2 --parts 10,28 --part-mode sequential,parallel --mergers pypdf,pymupdf --repeats 3 --qa off
```

Исторический научный профиль с полной QA, фиксированной геометрией и3 повторами, этап1000 только по допуску200:

```text
test scientific --codes 1000 --mergers pypdf,pymupdf
```

Малый пример для проверки команды/установки, без большого прогона:

```text
test pipeline --codes 3 --split cores:1+0 --schedule queue --batch 1 --repeats 1 --metrics off --qa off
```

## Общие параметры lab / pipeline / search

| Команда | Значения | Значение |
|---|---|---|
| `--codes` | `2000` или `200,1000,10000` | Положительные количества кодов; искусственного лимита10000 нет, ресурсные проверки остаются |
| `--repeats` | 1–10, по умолчанию3 | Измеренных повторов каждого варианта |
| `--qa` | `full`/`on`, `vector`, `off`/`deferred` | Полная QA, без растровых образцов или без QA; по умолчанию полная |
| `--module` | 0.25–2.0, по умолчанию0.5 | Размер модуля в мм |
| `--quiet` | 4–20, по умолчанию4 | Белое поле, модулей |
| `--ink` | четыре числа0–100, например `0,0,0,100` | CMYK; повторяющиеся нули сохраняются; K100 — только чёрная краска |
| `--pdf` | `standard`, `compact` | PDF-профиль, по умолчанию compact; у lab/search допустим список |
| `--metrics` | `off`, `cpu` | Подробные CPU-замеры; по умолчанию off; lab/pipeline принимают `off,cpu`, search один режим на команду |
| `--batch` | 1–1000, по умолчанию32 | Кодов в одной порции; pipeline/search принимают список; lab один размер на строку |
| `--ram` | `auto`, `50%`, `80%`, `max` | Безопасный бюджет с резервом ОС; без принудительного заполнения памяти |

`--qa off` создаёт UNVERIFIED, quality_checks=0. Это не ошибка и не QA PASS. После полной QA каждый сохранённый векторный код проверяется, первый/средний/последний растр декодируются. Отсутствующий renderer не выдаётся за полную проверку. Настройки физического размера определяются модулем и белым полем: (21+2×поле)×модуль мм.

## Дополнительно для lab

| Параметр | Значения |
|---|---|
| `--unit` | `cores`/`physical`, `smt`/`logical`, либо список обоих |
| `--cpu` | `1,2,4,6,8,12,all-2,all` или свой набор положительных чисел |
| `--backend` | `serial`, `process`, `thread`, либо список; по умолчанию process |
| `--ram` | Также список бюджетов и точные значения вроде `2048MiB` |
| `--warmups` | 0–3, по умолчанию0; пробные PDF, исключённые из итоговых замеров |
| `--workers` | 0 автоматически по CPU или своё число; не больше выбранных CPU |
| `--files` | `multipage`, `singles`, `both`; по умолчанию один многостраничный |
| `--activity` | `normal`, `minimal`, либо список; по умолчанию minimal |

Формула матрицы: тиражи × количества CPU × типы CPU × способы × бюджетыRAM × PDF-профили × расходы × режимыCPU-замеров. Каждый вариант имеет repeats замеров и warmups отдельных пробных запусков. Недоступные/эквивалентные CPU-наборы явно SKIPPED. Набор CPU — разрешённая область, не обещание100% нагрузки всех ядер.

## Дополнительно для pipeline

| Параметр | Значения |
|---|---|
| `--split` | Список `cores:12+2,smt:24+4,cores:14+0,smt:28+0` либо свои числа |
| `--schedule` | `equal`, `queue`, либо оба; по умолчанию оба |

Слева CPU для QR, справа CPU для геометрии/сжатия PDF. PDF=0: полный цикл в каждом процессе. Окончательный сборщик один и разделяет выбранный набор. Равные части закрепляют диапазоны за процессами обоих этапов; очередь отдаёт порцию свободному. Матрица: тиражи × распределенияCPU × способы × размеры порции × режимыCPU-замеров × повторы. У pipeline один бюджетRAM и один PDF-профиль на строку; несколько строк позволяют сравнить их без скрытой оси.

## Дополнительно для search

| Параметр | Значения |
|---|---|
| `--unit`, `--cpu`, `--backend` | Как в lab |
| `--each-cpu` | `on`: каждое доступное количествоCPU; `off`: ровно выбранные `--cpu`; по умолчанию off |
| `--search` | `full`: выбранные прямые варианты; `staged`: отбор лидеров и крайних CPU; по умолчанию full |
| `--keep-best` | 1–8, по умолчанию2 |
| `--parts` | Список2–1024, например `10,14,28`; по умолчанию10 |
| `--part-mode` | `sequential`, `parallel`, либо оба |
| `--mergers` | Ключи из списка ниже или `all`; по умолчанию pypdf |
| `--activity` | normal/minimal, список |
| `--ram` | Один бюджет или `2048MiB` |

Движки: `qpdf`, `mutool`, `pymupdf`, `pikepdf`, `pypdf`, `pdfrw`, `pdfium`, `pdfcpu`, `pdfbox`, `pdf-lib`, `pdfsharp`. Отсутствующие адаптеры получают SKIPPED и не устанавливаются автоматически. pikepdf/qpdf и PyMuPDF/mutool имеют общие семейства; это не11 независимых ядер.

Разбивка использует лучший фактически измеренный прямой профиль для каждого размера/типаCPU и максимальный выбранный CPU-набор. `full` не означает полный декартов перебор всех профилей разбивки; охват отражён в отчёте. Медиана ранжируется по полному времени с выбранной QA. У staged число запусков показывается как верхняя оценка.

## scientific

Только `--codes 200|1000|10000|all` и `--mergers`. Всегда3 повтора, QR V1-M,0.5мм, поле4,CMYK K100, полная QA. Следующий размер допускается по прежним правилам. Direct PDF входит обязательно; список mergers ограничивает объединители. Остальные переключатели этой методики не меняются.

## Результаты и архив

Папка очереди содержит `commands.txt`, `commands.json`, `commands.html`, исходные результаты каждой команды в runs/. JSON/HTML очереди содержат и настройки, и индивидуальные результаты — их можно показать ИИ. В исходных папках PDF остаются, автоматически не удаляются.

Локальный архив содержит только текстовые HTML/JSON/TXT, данныеCPU/RAM/ОС, версии, параметры, тайминги, статусы и ошибки. PDF/входныеTXT/QR-матрицы/сами номера кодов в новый текстовый архив не копируются. Автоархивирование идёт после измерений. Статус операции не меняется из-за ошибки архива; сообщение «АРХИВ НЕ СОХРАНЁН» и archive-status.json показывают её отдельно.

Кнопка **Добавить старые тесты** сохраняет текстовые снимки предыдущих lab/pipeline/search/scientific/suite/benchmark. Она не запускает тесты/QA и не меняет исходные отчёты. Повторный импорт того же результата не создаёт дубликат.

## Настоящий терминал

Те же параметры доступны снаружи GUI:

```text
.venv\Scripts\python.exe -m ucode test --plan pipeline --codes 1000,10000 --split cores:12+2,smt:24+4 --schedule equal,queue --repeats 3 --qa off
.venv\Scripts\python.exe -m ucode test pipeline --codes 3 --split cores:1+0 --schedule queue --repeats 1 --qa off
.venv\Scripts\python.exe -m ucode test help
.venv\Scripts\python.exe -m ucode test --plan --file команды.txt
```

`--plan` ничего не генерирует. `--file команды.txt` выполняет очередь изTXT, также совместим с--plan. Во встроенную консоль вставляется только строка, начинающаяся с `test`, без Python-пути. ВнешнийCLI возвращает0 для COMPLETE,2 для UNVERIFIED/LIMITED,1 для ошибки. Устаревшие команды `lab`, `pc-search`, `generate`, `benchmark` сохранены совместимыми. Отдельные серии используют frozen runtime; изменение исходников между командами останавливает очередь, сохраняя завершённые результаты. Зависимости во время серии не обновляйте.
