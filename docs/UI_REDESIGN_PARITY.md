## Новый порядок и взаимодействие

Тип → База → Путь → Оформление → Настройка → Просмотр → Тесты → Другое.

В первых пяти разделах только подготовка рабочего заказа. Кнопка создания и управление просмотром появляются в Просмотре. Тесты имеют независимые параметры, общие пресеты не добавляются. Наличие интерфейса тестов в прототипе не запускает реальные бенчмарки.

Меню закрывается кликом снаружи и Esc. Выделение текста интерфейса выключено по умолчанию; поля ввода остаются редактируемыми. Лицензия/контакты и центрированная статистика — плоские текстовые действия с видимым клавиатурным фокусом.

## Проверка пути относится к версии заказа

В подпись проверки входят исходные строки/тираж, политика повторов, геометрия/CMYK/фон, формат и количество PDF, настройки генерации и выбранная папка. При изменении подписи предыдущая проверка недействительна. Масштаб шрифта таблицы, тема, выбранная строка и параметры лаборатории не изменяют рабочий заказ.

Запуск при устаревшей проверке имеет `aria-disabled`, но остаётся доступным для перехода в Путь. Реальная генерация из него не стартует. Native disabled для этой кнопки непригоден: он не позволяет обработать переход пользователя.

В прототипе «Проверить · демо» использует явно условные данные. Это демонстрация жизненного цикла, а не проверка свободного места. До функционального переноса обязательны реальное измерение свободного места/единицы выделения файловой системы/права записи, калибровка по движку и формату, учёт временных файлов и контроль во время записи. Коэффициент запаса не гарантирует место при стороннем заполнении диска.

## Рабочий перенос 0.3.0

Итоговый главный интерфейс использует исходную HTML-вёрстку и `operator-bridge.js` с локальным `operator_web` / `operator_service`. Все лабораторные поля читаются из настоящих LabConfig/PipelineConfig/SearchConfig; конфигурации и команды остаются прежними. Исходный BatchWindow сохраняется как gui-legacy, промежуточный native-каркас также сохранён. Реальные TXT/preview/диск/PDF/QA/операционный процесс и текстовый архив подключены. Фон поддерживается всеми четырьмя PDF-путями и строгой QA. Основной API/HTML проверяется в `test_operator_web`, модели — `test_operator_models`, дочерний процесс — `test_operation_host`, PDF — `test_background_pdf`; прежние тесты сохраняются. [Подробная архитектура](WEB_OPERATOR_ARCHITECTURE.md).

## Границы проверки

- Сохранённый HTML остаётся образцом. Рабочее приложение на Tk использует реальные движки, архив и диск; пользовательский проход мышью с системными диалогами не подтверждён.
- GPU, серверная публикация и полный English не заявлены готовыми. Фон и остановка Windows Job Object проверены малыми автоматическими тестами.
- Native Alt+F4/WM_CLOSE проверяется отдельно; закрытие браузера/принудительное завершение ОС не подчиняется диалогу прототипа.
- 69 исходных полей сохранены в контрактах; прежние лабораторные контролы используются повторно. Тесты конфигураций/консоли и новый Tk smoke проверяют отдельные границы; это не утверждение о ручном клике по каждому из 69 полей.
- Визуальную приёмку выполняет пользователь. Проверка синтаксиса/чистых функций не считается GUI end-to-end.
