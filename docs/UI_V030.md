# uCode 0.3.0 — рабочий интерфейс

Утверждённый HTML-образец сохранён без изменений в `docs/design/approved-2026-10-30/`; контрольная сумма находится в manifest.json. Рабочая программа — native Python/Tk, HTML не служит оболочкой генерации.

## Запуск и рабочий сценарий

После установки зависимостей через `Setup-PDF.cmd` откройте `Start-uCode.cmd` двойным кликом. На существующей тестовой установке используется её `.venv`, повторная установка не требуется. Команда `python -m ucode gui` открывает тот же интерфейс. `Start-uCode-Legacy.cmd` / `python -m ucode gui-legacy` сохраняют исходное окно версии 0.2.

1. **Тип** — QR работает, три будущих модуля показаны с образцами и пометкой «В разработке».
2. **База** — открыть свой TXT либо создать последовательность (начало, количество, шаг). Ведущие нули сохраняются, последняя строка показывается до сохранения. TXT можно сохранить отдельно от PDF.
3. **Путь** — выбрать папку и проверить запись/место. Выполняются flush/fsync, определение единицы выделения файлов и калибровка до трёх настоящих страниц. Запас: 4 × (оценка PDF + временные данные + отчёты) + max(2 ГиБ, 10% свободного места). Это консервативная оценка, не обещание размера. Во время работы действует защита оставшегося места.
4. **Оформление** — размер, поле от четырёх модулей, экземпляры, четыре CMYK-канала кода и подложки, K100, белый/цветной/прозрачный фон. Изменения сразу отражаются в предпросмотре. Прозрачный PDF проверяется на белой подложке просмотрщика; цвет и инверсия проходят отдельную QA.
5. **Настройка** — физические ядра или SMT, один/все −2/все/свой выбор; процессы/последовательно/экспериментальные потоки, порция; PDF, QA, полезная RAM и статистика. По умолчанию новой установки: все доступные физические ядра, максимум безопасной RAM, компактный PDF, минимум расходов, QA выключена, подробные замеры и XY включены. Существующие сохранённые параметры загружаются совместимо. Использование всей RAM не означает искусственного заполнения памяти. PDF-сборка обычной генерации остаётся последовательной; альтернативные конвейеры находятся в тестах.
6. **Просмотр** — настоящая выбранная матрица QR, дисковый список, переход к строке, первая/последняя, поиск по всей базе до трёх совпадений, шрифт 8–32 px. Создание PDF доступно только здесь. При устаревшей проверке папки кнопка переводит в «Путь»; генерация не начинается.
7. **Тесты** — все существующие лаборатории, конвейер, подбор ПК, исторический научный профиль, консоль, архив и история. Параметры PDF теста находятся в отдельном подразделе и сохраняются независимо от рабочего заказа. Методика научного профиля не изменена.
8. **Другое** — встроенная/браузерная справка, контакты, сведения о лицензии, исходная лаборатория объединения и восстановление настроек.

## Выполнение и статистика

Генерация работает в отдельном процессе. Windows Job Object или Linux session/process group содержат только собственное дерево процессов. Во время операции управление и горячие клавиши блокируются; STOP/обычное закрытие требуют подтверждения с задержкой 3 секунды. Принудительная остановка закрывает собственное дерево; уже созданные файлы сохраняются, незавершённый PDF может быть непригоден. Закрытие через диспетчер задач и потерю питания перехватить невозможно.

Фазы измеряются движком отдельно. `launcher_wall` дополнительно включает запуск процесса и окончание ресурсных замеров, исключая финальную сериализацию HTML/архива. В отчёте эти области измерения подписаны отдельно. CPU min/mean/max — интервальные замеры собственных процессов, не доказательство постоянной 100% загрузки ПК. У короткого запуска выборки может быть недостаточно; отсутствие данных не заменяется нулями.

После создания доступны PDF, папка, `ОТЧЁТ.txt`, `production.html`, `manifest.json`, подробные JSON/CSV и локальный текстовый архив. Графики и XY используют реальные наблюдения. Один производственный запуск не становится трёхкратным научным сравнением. Без QA сохраняется **UNVERIFIED**, а не QA PASS. Архив исключает PDF, исходные коды, машинные пути и учётные данные. Внешняя отправка без подключённого сервера не выполняется.

## Обновление и возврат

Скачайте исходный ZIP релиза в **новую папку**. Существующую папку, результаты, `.venv` и локальные изменения не перезаписывайте. Для нового места выполните `Setup-PDF.cmd`, затем `Start-uCode.cmd`. Для сохранения предпочтений скопируйте свою `.local-state` после закрытия программы; абсолютный путь назначения проверьте во вкладке «Путь». Старые результаты можно импортировать через архив/историю. Альтернативный путь — обновление чистого Git checkout через fast-forward, только после сохранения собственных изменений.

Возврат: запустить сохранённый релиз v0.2.0 из отдельной папки либо `Start-uCode-Legacy.cmd` для прежнего окна на текущем движке. Пользовательские PDF и старые запуски не удаляются и не перезаписываются.

## Границы выпуска

Визуальную приёмку и крупные нагрузки выполняет пользователь. Автоматические проверки используют только малые PDF и программный Tk. GPU, другие кодировщики QR, новые типы штрихкодов и серверная публикация не объявляются подключёнными. Полная локализация English остаётся отдельным незакрытым пунктом дизайна: текущий рабочий интерфейс и справка на русском. Макет не является доказательством работоспособности этих будущих функций.
