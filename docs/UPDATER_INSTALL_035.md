# uCode — безопасное обновление Windows и архив интерфейсов

**Статус:** реализация в PR #33, не stable-релиз. Не путать код из feature-ветки с установленным у пользователя uCode 0.3.4.

## Зачем понадобилась новая схема

Официальная версия v0.3.4 публиковалась как portable ZIP. В ней независимый
uCode.Updater.exe 0.1.0 проверял версии, но **не устанавливал** обновления.
Чтобы заменить этот механизм, сначала необходимо **однократно установить новую
сборку**. Выпустить её с прежним номером 0.3.4 и перезаписать старый релиз
запрещено. Нужен новый проверенный выпуск (например v0.3.5).

## Управляемая установка (Windows)

При наличии более нового опубликованного стабильного GitHub Release:

1. Пользователь проверяет выпуск во вкладке «Обновление».
2. Нажимает «Установить» и подтверждает полное закрытие uCode.
3. Независимый updater заново запрашивает и проверяет стабильный релиз.
4. Через HTTPS скачивает SHA256SUMS.txt и архив Windows x64; проверяет
   размер и SHA256 **до распаковки**. Распаковка запрещает ссылки,
   недопустимые пути, повторные имена и чрезмерный объём.
5. Новая программа распаковывается **в отдельную версию**; запускается
   настоящий упакованный uCode.exe --smoke (две страницы PDF, QA LIMITED).
6. Только после PASS перемещает версию в каталог versions, атомарно
   переключает install-state.json и фиксирует предыдущую версию.
7. Для первого управляемого релиза создаёт отдельный launcher
   uCode.Updater.exe и, если одноимённого ярлыка нет, ярлык uCode на
   рабочем столе. Старый пользовательский ярлык не перезаписывает.
8. Когда текущая программа штатно закрылась, запускает новую.

Каталоги Windows:
- Бинарники: %LOCALAPPDATA%\uBrand\uCode-App\versions\vX.Y.Z\uCode
- Постоянный launcher: %LOCALAPPDATA%\uBrand\uCode-App\uCode.Updater.exe
- TXT/PDF/конфигурация/журналы: %LOCALAPPDATA%\uBrand\uCode
- Исходный ZIP и пользовательская прежняя portable-папка **не изменяются**.

Rollback в managed-установке: uCode.Updater.exe --rollback --accept,
после чего uCode.Updater.exe --launch. Данные проекта и предыдущие
бинарники не удаляются. При ошибке скачивания/проверки указатель
на прежнюю версию не меняется.

Ограничения текущего кандидата:
- Механизм устанавливает **только последующий** stable-релиз. Номер main
  в текущей preview-сборке ещё 0.3.4; preview из GitHub Actions теперь
  помечается каналом Development и commit SHA, стабильный релиз сохраняет
  канал Stable.
- GitHub Releases и HTTPS являются границей доверия; SHA256SUMS.txt из
  того же релиза не заменяет отдельную подписанную издателем подпись.
- macOS/Linux install/rollback ещё не реализованы.
- Автоматический rollback проверяется пока на этапе установки и smoke;
  реальную Windows GUI-приёмку и зависания/краши после запуска нужно
  проверить отдельно до stable.
- Проверка проводится на GitHub-hosted Windows и затем на компьютере
  владельца. Наличие кода не равняется завершённой установке.
- Выделенный каталог менеджера не должен содержать пользовательские
  файлы. Сборка их не удаляет и не перезаписывает.

## Автоснимки версий

Capture для v0.3.4 уже прошёл CI; скрипт входит в main. В PR #33 добавлена
опциональная **постоянная публикация** в отдельную ветку history-gallery:
отдельные папки history/vX.Y.Z, PNG, manifest с SHA256. Создание возможно
после появления workflow в main: **автоматически после слияния изменений
workflow (один раз снимет v0.3.4)** и при публикации каждого нового стабильного
релиза. Дополнительно есть ручной запуск (workflow_dispatch, tag=v0.3.4,
publish_history=true), но он не нужен при успешном первичном запуске. Существующий снимок версии не перезаписывается.

Это отдельная ветка, она **не** переписывает stable Assets/исходники и не
влияет на обновлятор. Перед будущим переводом uCode-Bench в PRIVATE
архив нужно перенести в публичный uCode — сейчас это не сделано.
