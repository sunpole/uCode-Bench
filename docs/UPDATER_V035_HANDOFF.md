# uCode 0.3.5 — центр обновлений и независимый updater: инженерный handoff

**Дата:** 2026-10-30. **Автор текущей реализации:** ChatGPT (GitHub connector), **следующий исполнитель:** ChatGPT Codex.
**Рабочая ветка:** `codex/v035-native-updater-tab`, **draft PR:** https://github.com/sunpole/uCode-Bench/pull/29, **основание:** `codex/v035-update-check` (PR #28 → `main`).
**Стабильный выпуск, который нельзя менять:** https://github.com/sunpole/uCode-Bench/releases/tag/v0.3.4 — подтверждённый stable, main на коммите `b2562a1` на момент решения; следить за новыми SHA.

## Роли и зона ответственности

- **Ведущий архитектор приложения / интегратор:** контракт между UI, loopback API, независимым updater и архивами GitHub; отсутствие зависимости обновлятора от HTML/WebView2/Python.
- **Senior Windows/.NET инженер:** self-contained single-file `uCode.Updater.exe`, жизненный цикл запуска, блокировка одновременных установок, подтверждение целевого каталога, права и откат.
- **Senior Python/PyInstaller инженер:** `operator_web`, `operator_desktop`, запаковка native binary в portable folder; никаких системных глобальных установок.
- **Senior UI/UX дизайнер:** аккуратная девятая вкладка «Обновление», темная/светлая темы, читаемый статус, компактный адаптивный layout, клавиатура и screen reader.
- **Инженер безопасности приложений:** строгий источник GitHub, SHA-256/подпись манифеста, без silent update, запрет path traversal, symlink, zip-bomb, перезаписи пользовательских данных и непроверенных бинарников.
- **QA/Release инженер:** offline mock тесты, реальные Windows CI и упакованный EXE, сохранение тестовых PDF, публикация только проверенных Release; `main` и `v0.3.4` неизменны без PR.

## Решение пользователя

> Сделать независимый `uCode.Updater.exe` и добавить отдельную новую, аккуратно оформленную, информативную и удобную вкладку обновлений внутри uCode. Будущий нативный интерфейс без HTML должен использовать тот же updater; в GitHub оставить для Codex точную передачу.

**Архитектурное обязательство:** нативный updater не зависит от реализации GUI. Кнопка вызывает согласованный протокол; пользовательские `output/`, TXT, PDF, архивы, `.local-state/` хранятся вне заменяемой версии. Никакого фонового обновления или тайной установки.

## Что уже написано в PR #29 (требует финальной QA)

1. `ucode/assets/operator-updates.js` — девятая вкладка «Обновление» с номером установленной версии, последним стабильным выпуском, платформой, статусом, пакетом и подсказками о безопасности. Кнопки: «Проверить обновления», «Открыть выпуски GitHub», неактивная «Установить обновление».
2. `ucode/assets/operator-updates.css` — ограниченные префиксом `#ucode-layout` адаптивные стили с существующей цветовой палитрой. Исходный `operator-approved.html` **не модифицирован**, его SHA-256 обязателен.
3. `ucode/operator_web.py` — подключает два независимых файла в существующий документ, только по пользовательскому POST с локальным токеном проверяет GitHub; `GET update-info` не вызывает сеть; `updates-open` открывает фиксированный URL.
4. `updater/uCode.Updater.csproj`, `updater/Program.cs` — независимая .NET 8 программа: `--check --installed 0.3.4` для read-only GitHub Releases, `--version`, `--self-test`. `--install` **явно не поддерживается**, не менять файлы.
5. `tests/test_update_center.py` — immutable макет, отображение, отсутствие фоновой сети, авторизация POST, фиксированная ссылка. `.github/workflows/native-updater-preview.yml` — сборка Windows x64 self-contained single-file, offline self-test и SHA256 артефакт.

## Следующие обязательные шаги Codex

**U02-A: Проверка и интеграция, до какой-либо установки**

- Проверить соответствие синтаксиса JS и Python, рендер и навигацию вкладки, темную/светлую темы, DPI 100/125/150%, Accessibility, отсутствие побочных изменений `operator-approved.html`.
- Проверить GitHub Windows compilation CI независимого EXE; исправить ошибки компиляции/типов/JSON, провести реальные `--self-test`, `--check` и offline отрицательные кейсы.
- Подключить независимый `uCode.Updater.exe` к упакованному Windows uCode при сборке, дать loopback bridge безопасно вызывать именно его для проверки; в исходном/dev режиме допускается existing `ucode.update_check` при отсутствии updater.
- Не передавать URL или произвольные аргументы из браузера в процесс updater; только строгие внутренние константы и установленную версию. CLI JSON контракт валидировать по схеме.
- Протестировать отсутствие зависаний во время генерации, отказ при отсутствии сети, отмену проверки, закрытие приложения; записать реальные CI run IDs/commit SHA/ограничения.

**U02-B: Скачивание и безопасная установка — ЕЩЁ НЕ РЕАЛИЗОВАНО**

- Проектный versioned install: `app/versions/vX.Y.Z/`, разделённая пользовательская папка, фиксированный bootstrap, запись temp → проверенный SHA-256 и релизный manifest → безопасная распаковка без traversal/symlink → самотест → закрытие программы → атомарное переключение активной версии и резерв на rollback. Никакой замены исполняемого файла самого обновлятора на лету.
- Определить границы доверия: SHA256 из того же непроверенного источника недостаточен против подмены релиза; лучше подпись release manifest с закрепленным ключом либо подтверждённое доверие к GitHub и HTTPS с ясным ограничением.
- Показать версию и изменения до нажатия «Установить»; отдельное подтверждение, прогресс байтов, Cancel, rollback, тестирование отказов сети/диска/прав, отсутствие записи в старый релиз.
- Только после PASS и явного согласия пользователя включать кнопку установки.

**U03: отдельно macOS/Linux** — нативная упаковка/проверка и соответствующие права, Gatekeeper/sign/notarization; Windows .NET EXE сам по себе не кроссплатформенный пакет.

## Запреты и границы

- **Не реализовывать QR с переменной длиной чисел**: пользователь отказался из-за отсутствия потребности, решение хранится в `docs/QR_VARIABLE_DATA_PLAN.md`.
- **Не объявлять auto update работающим**, пока нет реального end-to-end `download+verify+install+rollback`; текущий U02 — read-only.
- Никаких `git clean/reset --hard` в локальном проекте пользователя. Рабочая папка `016_uCode_PDF_test` сохраняет локальную работу, для просмотра есть `016_uCode_GitHub_preview`. Пользователь предпочитает **Git Bash Here** и короткие команды.
- Стабильная v0.3.4 опубликована, старый AI_HANDOFF содержит исторические (устаревшие) состояния — читать последние дополнения.
- Перед каждым новым шагом обновлять `docs/WORK_LOG.md` фактами, ссылками на CI, SHA, статусами. Не смешивать `PASS`, `LIMITED`, `USER-CHECK` и `TODO`.
