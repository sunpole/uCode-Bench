# uCode v0.2 — проверка и границы доказательств

Дата: 27.10.2026. PR: https://github.com/sunpole/uCode-Bench/pull/2. Основа актуального GitHub/ПК: 4ac6bd9. Тестовая копия `016_uCode_PDF_test`; ветка `feature/unified-ui-v0.2-20261027`. Исходники в соседней `016_uCode` и `main` не менялись.

## Что реализовано

- Один основной Tk экран, общие точки входа Start-uCode.cmd / PDF-from-TXT.cmd, меню TXT/номера/тип/настройки/тесты/справка. Постоянных полей настроек, инженерного лога и прокруток нет.
- GUI считает кодирование, запись страниц и QA по реально выполненным элементам. Общий процент монотонен, 100% после полной проверки и сохранения отчёта. Секундомер работает через Tk after, рабочий поток не вызывает Tk. Отмена сохраняет файлы и статус; неполная проверка остаётся LIMITED.
- Цвет CMYK проверяется по заданным компонентам; K100 отдельно. Геометрия сохранена. Настройки размера/поля/цвета/режима сохраняются в проектной .local-state, не в Windows registry.
- Генераторный Protocol + работающий QR + явные будущие EAN-13/Code128/DataMatrix. Научный runner 200→1000→10000 с тремя повторами, проверкой предыдущего отчёта/хешей/QA и RAM/диска. Производственные данные отделены от научных.
- Launcher распознаёт отсутствующий/неподходящий Python, выводит сообщение и не устанавливает зависимости сам. Pythonw освобождает стартовый терминал. Окно учитывает реальные запрошенные размеры Tk при DPI.

Workflow txt-batch.yml расширен: полные регрессии, Tk под Xvfb в Linux, Poppler, реальные PDF 200/1000/10000 и цветной режим, сохранение evidence. Первый Linux CI (40556940849) PASS. Первый Windows прогон остановлен: стек указывает на difflib в старом test_pdfsharp при сравнении 1000 путей. Диагностический повтор подтвердил 8.3 alias TEMP (RUNNER~1 вместо runneradmin) ещё в пяти старых проверках external adapters. Ожидания тестов приведены к каноническим путям validate_paths, сравнение PDFsharp по одному элементу исключает долгое построение diff. Адаптеры не менялись, проверки порядка/Unicode/argv/сохранности файлов сохранены. Исходный журнал сохранён в output/v02-ci-first-windows.log. Итог повторного CI фиксируется после завершения; не считать конфигурацию workflow доказательством прохождения.
