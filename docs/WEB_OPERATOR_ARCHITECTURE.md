# Локальный интерфейс утверждённого дизайна

## Модули

- `assets/operator-approved.html`: неизменённый утверждённый образец; SHA256 `b86287a4413e4e32b51a46a6ca8b8c1a7278d627b0d4b0ee97612992e9bd863a`.
- `operator_web.document`: проверяет хеш, сохраняет все 18 блоков CSS/построение макета, удаляет внешний CDN и вставляет `operator-bridge.js` вместо демонстрационных действий. Файл образца не переписывается.
- `operator-bridge.js`: привязка существующих экранов и контролов к реальным операциям; собственные лабораторные конфигурации, полностью отдельные от заказа. Центральная высота адаптируется к окну, шапка/управление/подвал сохраняют расположение.
- `operator_service`: единый активный слот, настройки, SQLite-индекс, поиск, оценка диска, подпись заказа, результат и каталог.
- `operator_models`: общие проверенные модели последовательностей, форматирования, источника и допуска по диску.
- `operation_host` / `operation_worker` / `operator_test_worker`: собственное дерево процессов; прежние функции генерации/QA/лабораторий/консоли не переписаны под браузер. Пул QR и последовательная запись PDF сохраняют свои честные границы.
- `native_dialog`: отдельный процесс только для пользовательского Проводника/сохранения, чтобы не вызывать Tk из HTTP-потока.
- `operator_help`: описание актуальных вкладок; прежняя справка сохраняется для gui-legacy.

## Границы и сохранность

Только loopback, случайный непубликуемый ключ сеанса, проверки Host/Origin/POST, CSP без сторонних скриптов. Нет произвольной shell-консоли или HTTP-доступа ко всем файлам ПК. Выбор файлов выполняется пользователем в системном диалоге; результаты открываются по зарегистрированным путям результата/архива/истории. Новый сервер не слушает LAN и не делает программу облачной.

Сохранение: `.local-state/user-settings.json` совместим с предыдущим GUI; `web-ui.json` содержит тему, плотность строк, последний индекс и отдельные конфигурации тестов. Старые lab/pipeline/search-настройки загружаются. Индекс восстанавливается только при неизменённых исходнике и SQLite; перед генерацией дополнительно проверяется SHA256 TXT. Проверка пути зависит от содержимого/настроек заказа. Тема/шрифт/выбранная строка/параметры тестов её не меняют.

Живые замеры относятся к собственному дереву процессов. Минимум/среднее/максимум — интервальные наблюдения, короткий запуск может дать INSUFFICIENT_SAMPLES. Графики и архив используют сохранённые данные, не запускают PDF заново. В архив не копируются PDF и исходные коды. Отправка на VPS без заданного сервера отсутствует.

Повторный запуск подключается к живому сеансу. Проектная OS-блокировка предотвращает второй генератор при одновременном двойном клике. Закрытие браузера не останавливает активную операцию; повторный запуск возвращает управление. Неактивный незанятый сеанс завершается через 60 секунд. STOP требует серверного nonce и выдержки не менее трёх секунд.

## Проверка и изменения

`tests/test_operator_web.py` проверяет реальный loopback API, PDF и малый лабораторный прогон, неизменённые стили, исходные 69 полей, защиту API и задержку остановки. Node проверяет JS без установки Node на пользовательском ПК. Полный CI Windows/Linux сохраняет прежние тесты/малые PDF-smoke.

Визуальная приёмка, Windows DPI и большие нагрузки — пользовательские. Ни программное сравнение CSS, ни проверка DOM не выдаются за формальную пиксельную приёмку.
